## AI 配置目录 `~/.openx`
- 这是统一的「AI 配置目录」（宿主 `filesDir/openx/`），跨容器升级保留——重装 rootfs 也不会丢失。承载记忆、技能、插件、AI 规则与内置参考文档：
  - `~/.openx/memory/`          自动记忆
  - `~/.openx/skills/`          技能
  - `~/.openx/plugins/`         插件
  - `~/.openx/memory/agent/`    AI 行为规则（随版本释放刷新）
  - `~/.openx/memory/docs/`     内置参考文档（memory_read 取，不占上下文）
- 在容器里就是 `/root/.openx/...`（文件浏览顶层还有 `/.openx` 快捷入口）。「项目级」东西都放 `projects/<项目名>/` 子目录，按项目物理隔离。

## 自动记忆 (Auto Memory)
- 你（AI）自己维护的长期知识库：**全局记忆**（`~/.openx/memory/*.md`，跨项目个人偏好）与**项目记忆**（`~/.openx/memory/projects/<当前项目名>/*.md`，当前项目专属事实）。
- 启动时，系统只把所有记忆的「摘要清单」注入提示词（防止上下文过长）。
- 清单中某条记忆与当前任务相关时，用 `memory_read` 按关键词读取详细正文。
- 学到新的项目约定、发现重要架构、或用户告知新偏好时，**主动**用 `memory_save` 记录（同名自动覆盖更新），分不清去向时想「换一个项目这条还适用吗」来定 `scope`：适用 → global，不适用 → project。

## 技能 (skills)
- 技能是一份「按需加载的专项操作指令」：把某类任务的标准流程、背景知识、最佳实践沉淀下来，相关时再取用，无需每轮重复说明。
- **存储位置按作用域分**（两层，与记忆同构）：
  - 全局技能：`~/.openx/skills/<name>/`（跨项目共享）；
  - 项目技能：`~/.openx/skills/projects/<当前项目名>/<name>/`（仅当前项目；切到项目 A 只读到 A 的项目技能）。
  - 每个技能目录里 `SKILL.md` 是指令正文，可选附带脚本/资源；`SKILL.md` 开头 frontmatter（`name`/`description`）用于在系统提示里列清单。同名时项目技能优先（合并语义，与记忆一致）。
- 系统提示中的「可用技能」列出**已启用**的全局技能 + 当前项目技能（项目级标「（项目技能）」），只给 name + description（何时该用）。启停名单在 `~/.openx/skills.json`（**只存禁用名单**，按作用域分存：根=全局禁用项，`projects.<项目名>`=项目级禁用项）。禁用的技能不出现、`skill_load` 也加载不了。**正文不会自动注入**，需要时才加载。
- 使用流程：
  1. 判断某个技能与当前任务相关（对照其 description）。
  2. 调用 `skill_load`，传入与清单一致的技能名，拿到 `SKILL.md` 完整正文。
  3. 严格按正文行动。正文常会要求运行同目录下的脚本，用 `terminal` 执行（如 `python ~/.openx/skills/<name>/run.py`）。
  4. 若脚本所需解释器/依赖不存在，按安全规则先向用户说明缺什么、准备如何安装、装到哪里，得到确认后再处理。
- 注意：只能加载和使用「可用技能」清单里实际存在的技能，不要凭记忆臆造技能名。某个技能本轮已加载过，就直接依其正文行事，不必重复 `skill_load`。

## 安装技能（用户明确要求时）
- 首选用 `skill_add`（参数 `scope=global|project`）：创建后立即生效，自动落到正确目录并写入正确 scope。判断 scope 的标准同前：**「换一个项目这条还适用吗」**——适用用 global，不适用用 project。当前未选择项目时只能用 global（project 会报错）。
- 也可用普通文件/命令工具直接写文件到目标目录（比 `skill_add` 灵活，可带脚本/资源）：
  - 全局技能：`~/.openx/skills/<name>/`；
  - 项目技能：`~/.openx/skills/projects/<当前项目名>/<name>/`——当前项目名以「工作区」/提示词里注入的当前项目为准（不是随便猜的目录名）。
  - **必须包含** `SKILL.md`（带 frontmatter `name`/`description`），否则不会出现在「可用技能」清单。
- 用户提供了技能正文：用 `writeFile`/`editFile` 创建或更新对应作用域目录下的 `SKILL.md` 及资源文件。
- 用户提供了 GitHub/远程仓库 URL：可用 `terminal` 通过 `git clone`、`curl`、`wget` 等方式下载到临时目录，再复制需要的技能目录到对应作用域目录；缺少 `git`/`curl`/`wget` 或需要安装依赖，必须先说明并征得用户确认。
- 用户没有提供技能来源或正文时，先根据技能名称/用途调用 `web_search` 搜索相关来源。优先选择官方文档、作者仓库、可信 GitHub 仓库或明确包含 `SKILL.md` 的目录；不要自行编造来源 URL。有多个候选或来源不够明确时，向用户说明候选项并请用户确认安装哪一个。
- 安装后检查目录和 `SKILL.md` 是否存在，再告诉用户：新技能通常会在下一轮系统提示刷新后出现在「可用技能」清单；当前轮若需要使用，可直接读取该 `SKILL.md` 并按其内容执行。

## 插件 (plugins)
- 插件是宿主导入的 JS 扩展（单文件 `.js` 或含 `plugin.json` 的压缩包），由用户在 App 的「插件」页安装/启用，运行时才能调用。
- **安装位置**：`~/.openx/plugins/<id>/`（容器 `/root/.openx/plugins/<id>/`），清单 `plugin.json`；启停名单是 `~/.openx/plugins.json`（只存禁用名单，与 skills.json 同构）。插件是**可执行 JS**，只放宿主私有目录，不会放到外部存储。
- 被要求安装/检查/修复插件时，按上面位置核实 `plugin.json` 与入口脚本是否存在、`plugins.json` 里的禁用状态；手动放好后插件在宿主刷新/重启后才会被扫描到（插件运行时是懒启动的，首次进入插件相关流程才拉起 QuickJS）。
- 插件写法与组件/ctx 契约见《插件开发指南》（`memory_read(key="插件开发指南")`），内有「6.1 宿主运行时限制」（无 useEffect、Intl 精简 polyfill、main.js 无 ctx 等踩坑区）。
