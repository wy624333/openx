## 1. 5 分钟上手

一个插件就是一个目录：

```
hello/
├── plugin.json      # 清单（必需）
├── main.js          # 工具入口（可选）
└── ui/
    └── panel.ui.js  # 界面入口（可选）
```

最小可用的 `plugin.json`：

```json
{
  "id": "my.hello",
  "name": "Hello 插件",
  "version": "1.0.0",
  "description": "我的第一个插件",
  "main": "main.js",
  "ui": "ui/panel.ui.js",
  "permissions": ["toast"],
  "quickActions": [
    { "label": "打开面板", "action": "openUi", "icon": "extension" },
    { "label": "浏览器打开", "action": "openUrl", "url": "http://127.0.0.1:18899/", "icon": "open_in_new" }
  ]
}
```

把它压成 zip，在 **插件管理 → 右上角「+」→ 添加压缩包插件** 里导入即可。

> 只要 zip 里**任意层级**存在 `plugin.json`，解压器就能识别出插件。
> 从 GitHub 下载的包常带一层 `repo-main/`，不用手动展平。

## 2. 目录结构与 plugin.json

### 字段说明

| 字段 | 必需 | 说明 |
|---|---|---|
| `id` | ✅ | 唯一标识，建议反向域名（`com.example.tool`）。也用作**卸载时的包名前缀依据** |
| `name` | ✅ | 显示名，出现在插件列表与界面标题 |
| `version` | | 版本号。内置插件靠它判断是否需要重新释放 |
| `description` | | 一句话说明，显示在卡片上 |
| `author` | | 作者名 |
| `main` | | 工具脚本，默认 `main.js` |
| `ui` | | 界面脚本，**留空表示这个插件没有界面** |
| `service` | | **服务脚本（2.6.7 新增）**，声明后插件详情页的「插件配置」页签出现启动入口，详见 [第 9 节](#9-服务型插件本地网关) |
| `port` | | 服务默认监听端口（2.6.7 新增，默认 18899；被占用自动顺延 +1，最多试 10 个） |
| `apiVersion` | | 目标宿主 API 版本，当前 `1.0.0` |
| `permissions` | | 权限数组，**不写 = 什么都不给**。详见 [第 6 节](#6-ctx-api-与权限) |
| `quickActions` | | 侧边栏快捷项，详见下 |
| `aiProvider` | | 对外声明一个本机 AI 供应商，详见下 |
| `settings` | | 声明配置项，宿主自动渲染成原生控件，详见下 |

### quickActions（侧边栏快捷项）

```json
{
  "quickActions": [
    { "label": "打开面板", "action": "openUi", "icon": "extension" },
    { "label": "浏览器打开", "action": "openUrl", "url": "http://127.0.0.1:18899/", "icon": "open_in_new" },
    { "label": "总结选中内容", "prompt": "请总结：", "icon": "list", "autoSend": false }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `label` | 按钮文字 |
| `action` | `"openUi"` = 直接打开本插件界面；`"openUrl"` = 用系统浏览器打开 `url`；`"prompt"`（默认）= 把 prompt 灌进聊天框 |
| `prompt` | `action: "prompt"` 时的提示词（该动作必填） |
| `url` | `action: "openUrl"` 时的地址（该动作必填）。适合插件起了本地网页服务、要拉到系统浏览器里用的场景（WebView 里用不了系统下载/分享/长按选择） |
| `icon` | 图标名，见 [图标表](#图标) |
| `autoSend` | 灌提示词后是否自动发送，默认 `false` |

> **注意**：两个动作各有一个必须填的字段，缺了点了就没反应：
> - `action: "openUi"` 要求 `ui` 非空；
> - `action: "openUrl"` 要求 `url` 非空（点了会提示「该快捷项未配置网址」），
>   走 `Intent.ACTION_VIEW` 交给系统浏览器，不受插件 `http` 权限影响。

### aiProvider（插件自带的 AI 供应商）

插件里跑了个 OpenAI 兼容服务（本地网关、模型代理…）时，用它把地址报给宿主，
用户不用再自己去「API 配置」里手填一条：

```json
{
  "aiProvider": {
    "name": "AI 网关（本机）",
    "baseUrl": "http://127.0.0.1:18791/v1",
    "apiKey": "",
    "model": ""
  }
}
```

| 字段 | 说明 |
|---|---|
| `name` | 供应商显示名；留空回退成插件名 |
| `baseUrl` | OpenAI 兼容根地址。宿主请求时拼的是 `baseUrl + "/chat/completions"`，所以**要带 `/v1`**（与其它 OpenAI 兼容供应商一致） |
| `apiKey` | 服务端要求的 Key。**留空 = 不覆盖**，用户自己在界面里填的 Key 会被保留 |
| `model` | 默认模型名，同样留空不覆盖用户的选择 |

行为：

- 插件**启用**时写入供应商（插件列表刷新时同步，幂等）；插件**禁用或卸载**时自动删掉。
- 列表里带「插件」小标签。地址与类型以清单为准——用户手改的地址在下一次插件刷新时会被清单值覆盖。
- 供应商 id 固定为 `plugin:<插件 id>`，不会和用户手填的条目撞。
- **不校验服务是否真在跑**：声明了就建条目。面板没启动时点发送只会报连接失败，不会拦住插件。
- 声明里没写 `baseUrl`（或为空）等于没声明，不会建条目。

### settings（宿主渲染的配置项）

在清单里把配置项描述出来，宿主就能在「插件管理 → 插件配置」页把它渲染成**原生控件**，
值直接写进插件 env。好处是：**宿主不必执行任何插件代码**就能画出配置页，
插件侧也不用自己写界面（写法见 [第 4 节](#4-界面ui指定插件页)）。

```json
{
  "settings": [
    { "key": "enabled", "type": "switch", "title": "开机自启", "default": "true" },
    { "key": "port",    "type": "number", "title": "监听端口", "default": "18899" },
    { "key": "level",   "type": "slider", "title": "日志级别", "min": 0, "max": 3, "default": "1" },
    { "key": "mode",    "type": "segment", "title": "路由模式", "default": "direct",
      "options": [ { "label": "直连", "value": "direct" }, { "label": "代理", "value": "proxy" } ] },
    { "key": "token",   "type": "text", "title": "访问令牌", "placeholder": "留空则不校验",
      "group": "安全" }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `key` | ✅ 存进 env 的键名。**留空这项会被忽略**（没键就没法存值） |
| `type` | 控件类型，见下表。留空或认不出都按 `text` 渲染，不会让整页画不出来 |
| `title` | 显示标题 |
| `desc` | 标题下方的小字说明 |
| `default` | 默认值：env 里**还没有这个键**时写入。用户改过的值不会被覆盖 |
| `options` | `segment` 的候选项数组，每项 `{ label, value }`（`label` 留空回退成 `value`） |
| `min` / `max` | `slider` 的上下界，默认 `0` / `100` |
| `placeholder` | `text` / `number` 输入框的占位文字 |
| `group` | 分组标题：**相邻**同组的项归到一个小节；留空归入无标题组 |

支持的 `type`：

| 值 | 渲染成 | 值怎么存 |
|---|---|---|
| `switch` | 开关 | 字符串 `"true"` / `"false"` |
| `segment` | 一行等宽胶囊，单选 | 选中项的 `value` |
| `slider` | 滑杆，右侧实时显示当前值 | 取整后的数字字符串 |
| `text` | 单行输入框 | 原文 |
| `number` | 同上，但弹数字键盘 | 原文 |

插件侧读值：

```js
// 需要 "env" 权限
var port = parseInt(ctx.getEnv('port') || '18899', 10);
var on   = ctx.getEnv('enabled') === 'true';
```

注意几点：

- **值都是字符串**。布尔用 `"true"` / `"false"`，数字自己 `parseInt` / `parseFloat`。
- env 与插件界面里的 `ctx.getEnv` / `ctx.setEnv` 是**同一份数据**：
  用户在配置页改完，面板脚本立刻读得到；面板里改的，回到配置页也是新值。
- 默认值只在**缺失**时补，插件升级/重装不会冲掉用户改过的值。
- 配置页的顺序固定：服务状态与启停（有 `service` / `schedule` 时）→ `settings` 各项
  → 「打开配置界面」（有 `ui` 时）→ 定时任务清单。
- 配置项的内容用户本来就要看要改，所以是**明文展示**，别把不该给人看见的东西往里放。

## 3. 注册工具（main.js）

工具让 AI 能调用你的代码。写法和 OpenX 内部的 JS 工具一致：

```js
var $ptools = $ptools || [];

$ptools.push({
  name: 'hello_greet',                       // 见下方命名约定
  description: '向某人问好。',                 // AI 靠这句话决定要不要调
  parameters: {
    type: 'object',
    properties: {
      who: { type: 'string', description: '打招呼的对象' }
    },
    required: ['who']
  },
  handler: function (args) {
    return JSON.stringify({ ok: true, message: '你好，' + args.who });
  }
});
```

### ⚠ 命名约定（重要）

**工具名第一个下划线之前的部分 = 包名**，宿主靠它做整体卸载。

| 工具名 | 包名 |
|---|---|
| `hello_greet` | `hello` |
| `hello_echo` | `hello` |
| `tts_speak` | `tts` |

同一个插件里的所有工具**必须用同一个前缀**，否则禁用插件时会有工具撤不掉。

### handler 约束

- 返回值会被序列化成字符串交给 AI —— **必须返回字符串**（通常 `JSON.stringify(...)`）
- **不支持 `async`**：宿主是同步调用 handler 的。要异步就从宿主侧发起、再轮询状态
- 抛异常会被宿主捕获并作为错误返回，不会崩界面

## 4. 写界面（ui/*.js）

界面用一套**声明式 DSL**（形如 Compose 的 API），由宿主渲染成原生 Compose 组件。

### 两种入口写法

```js
// 写法 A：CommonJS（推荐）
function Screen(ctx) { /* ... */ }
module.exports = Screen;

// 写法 B：CommonJS 具名
function Screen(ctx) { /* ... */ }
exports.default = Screen;

// 写法 C：全局函数
function Screen(ctx) { /* ... */ }   // 宿主会自动找到 globalThis.Screen
```

三种都支持，选一种即可。

### 最小界面

```js
function Screen(ctx) {
  const [count, setCount] = ctx.useState('count', 0);

  return ctx.UI.Column({ padding: 16 }, [
    ctx.UI.Text({ text: '计数：' + count, fontSize: 18, bold: true }),
    ctx.UI.Button({
      text: '+1',
      onClick: function () { setCount(count + 1); }
    })
  ]);
}
```

### 状态管理

| API | 说明 |
|---|---|
| `ctx.useState(key, init)` | 返回 `[值, setter]`。setter 支持函数式更新 `setCount(c => c + 1)` |
| `ctx.useMemo(key, fn, deps)` | 依赖不变时复用结果 |
| `ctx.useRef(key, init)` | 返回 `{ current }`，跨渲染保持但不触发重渲染 |

**`key` 必须全局唯一**（在同一界面内）。宿主用 key 存取状态。

> 状态是**唯一真相源在 JS 侧**，宿主只做镜像。所以"改 state → 自动重渲染"这条链路
> 永远一致，不会出现两边不同步。

### 事件处理

把函数直接传给 `onClick` / `onValueChange` 等属性即可：

```js
ctx.UI.Button({ text: '保存', onClick: handleSave })

ctx.UI.TextField({
  value: name,                    // 通常是 useState 的值
  onValueChange: setName,         // 收到的是**裸值**，不是 { value: ... }
  label: '名字'
})
```

**所有节点都支持长按**：额外传一个 `onLongClick` 即可（不需要点击的容器也能用，
比如画布、卡片、图片）。和 `onClick` 互不冲突：短按触发 `onClick`，按住到系统长按
阈值触发 `onLongClick`。

```js
ctx.UI.Canvas({ width: 120, height: 120, ops: [...],
  onClick: function () { pat(); },        // 点一下
  onLongClick: function () { menu(); }    // 长按
})
```

### 回调参数：裸值 vs payload

两种约定并存，写错会静默拿到 `undefined`（真机踩过）：

| 组件 | 回调收到 | 示例 |
| --- | --- | --- |
| `TextField` `Slider` `Switch` `Checkbox` `RadioButton` | **裸值** | `onValueChange: setName` |
| `Tabs` `Dropdown` | **整个 payload**（含 `index`/`value`/`label`） | `onSelect: p => setTab(p.index)` |

所以 Slider 要加工时得自己对裸值加工：`onValueChange: v => setVol(Math.round(v))`。

**最隐蔽的错误写法**（真机踩过，表现为「下拉框选什么都不变」）：

```js
// ❌ 错：p 是对象，p === 0 永远 false，三元永远走到最后一支
ctx.UI.DropdownMenu({
  items: ['A', 'B', 'C'],
  onSelect: function (p) { setMode(p === 0 ? 'a' : (p === 1 ? 'b' : 'c')); }
});

// ✅ 对：取 p.index
ctx.UI.DropdownMenu({
  items: ['A', 'B', 'C'],
  onSelect: function (p) { setMode(p.index === 0 ? 'a' : (p.index === 1 ? 'b' : 'c')); }
});
```

判断依据：宿主只对**显式声明要裸值**的组件拆包（TextField/Switch 这类），
Tabs/Dropdown 不拆 —— 因为它们的 `value` 字段是「选中项的值」，
拆了就丢掉 `index`，点标签永远切不动。

宿主会把函数包装成 action id，点击时回调进 JS。

### 条件渲染

用普通的三元表达式，`null` / `false` 会被忽略：

```js
enabled
  ? ctx.UI.Card({}, [ ctx.UI.Text({ text: '已启用' }) ])
  : ctx.UI.Text({ text: '（已关闭）', color: 'textsecondary' })
```

### 列表渲染

```js
ctx.UI.LazyColumn({}, items.map(function (it) {
  return ctx.UI.ListItem({ title: it.name, subtitle: it.desc, onClick: function () { pick(it); } });
}))
```

`Row` 加 `wrap: true` 会自动换行（适合标签云）：

```js
ctx.UI.Row({ wrap: true, horizontalArrangement: 'spacedBy' }, tags.map(...))
```

## 5. 组件参考

### 通用属性（所有组件可用）

| 属性 | 类型 | 说明 |
|---|---|---|
| `fillMaxWidth` / `fillMaxHeight` / `fillMaxSize` | bool | 撑满 |
| `width` / `height` | number \| `"fill"` | 尺寸（dp） |
| `size` | number | 宽高同值 |
| `padding` | number | 四边内边距 |
| `paddingHorizontal` / `paddingVertical` | number | 水平/垂直内边距 |
| `background` | 颜色 | 背景色（token 或 `#hex`） |
| `cornerRadius` | number | 圆角 |
| `clip` | bool | 裁剪（默认 8dp 圆角） |
| `alpha` | 0–1 | 不透明度 |
| `rotate` | number | 旋转角度（度，顺时针为正） |
| `scale` | number | 等比缩放（1 = 原大小） |
| `scaleX` / `scaleY` | number | 分轴缩放（优先于 `scale`） |
| `offsetX` / `offsetY` | number | 绘制偏移（dp，负值向上/向左） |
| `pivotX` / `pivotY` | 0–1 | 旋转与缩放的中心点（默认 0.5 = 中心；`pivotY: 1` = 底部） |
| `animate` | object | **宿主驱动的循环动画**，见下方「让它一直动」 |

#### 变换类属性（`alpha` / `rotate` / `scale` / `offsetX` / `offsetY`）

这些属性走绘制层，**只影响画面、不改变布局尺寸**：做呼吸、弹跳、倾斜、视差这类
动画时，周围控件不会被顶开，也不会因为动画触发重排。

```js
// 呼吸：每 150ms 用定时器推进相位，只改 scale（不改 width/height）
var s = 1 + 0.02 * Math.sin(tick * 0.33);
ctx.UI.Image({ src: 'asset://assets/pet.webp', width: 200, height: 200,
  scale: s, offsetY: Math.sin(tick * 0.15) * 2, rotate: Math.sin(tick * 0.07) * 1.2,
  pivotX: 0.5, pivotY: 1.0, alpha: 1 })
```

两点注意：

- 偏移是**绘制偏移**，不占位。它不会把后面的控件推开，也不会扩大可点击区域
- 变换后超出自身边界的内容仍会画出来（不被裁）。要裁就配 `clip: true`

#### 让它一直动：`animate`（呼吸 / 浮动 / 倾斜）

需要**不停循环**的小动作（呼吸、上下浮、轻微摇摆）用宿主内置的 `animate`，
不要自己开 `setInterval` 改 `offsetY`：

```js
ctx.UI.Image({ src: 'asset://assets/pet.webp', width: 200, height: 200,
  animate: {
    bob: 1.6, bobMs: 1800,          // 上下浮动幅度（dp）与周期
    tilt: 0.5, tiltMs: 4600,        // 左右摇摆角度（度）与周期
    breathe: 0.012, breatheMs: 2200 // 缩放呼及幅度（0.012 = ±1.2%）与周期
  } })
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `bob` / `bobMs` | 0 / 1800 | 上下浮动幅度（dp）、周期（ms） |
| `tilt` / `tiltMs` | 0 / 4200 | 摇摆角度（度）、周期（ms） |
| `breathe` / `breatheMs` | 0 / 2200 | 缩放幅度（0.01 = ±1%）、周期（ms） |

几个要点：

- 它是 **Compose 无限循环动画，60fps**，走 graphicsLayer（不影响布局）—— 零 JS 开销，
  也不会触发任何重渲染。用定时器改属性只能跑到几帧每秒，看着就是一跳一跳
- `animate` 与静态 `offsetY` / `rotate` / `scale` 是**叠加**关系（两层 graphicsLayer）：
  可以一边给静态姿态，一边让它呼吸
- 周期下限 200ms（写 0 也不会把主线程拖死）
- 所有值都为 0 时完全不生效，没有额外开销

### 包内素材（`asset://`）

图片想随插件一起分发（表情图、图标、背景），把文件放进插件目录，`src` 写
`asset://相对路径`：

```
你的插件/
  plugin.json
  ui/panel.ui.js
  assets/pet.webp        <- 放在插件目录里任何位置都行
```

```js

```

- 路径相对于**插件自己的安装目录**，不需要（也不能）写绝对路径
- 读包内素材**不需要 `file` 权限** —— 它是插件自己带的资源，不是用户文件

> 别把大图 base64 内联进 `ui/*.js`：每张图都会变成几倍体积的字符串，QuickJS
> 每次重渲染都要重新解析。几十张图请用 `asset://`。

### 画布（`Canvas`）
宿主唯一一个「自由绘制」组件：你给一维绘制指令，宿主逐条画。用来画图表、进度环、
矢量小图标、像素形象 —— 这些用盒子拼不出来，贴静态图又没法按状态改。

```js
ctx.UI.Canvas({ width: 120, height: 120, onClick: tap, ops: [
  { op: 'arc',   x: 20, y: 45, w: 80, h: 62, start: 0, sweep: 360, fill: '#F5A65B' },
  { op: 'circle', cx: 45, cy: 40, r: 6, fill: '#3A2A1E' },
  { op: 'circle', cx: 75, cy: 40, r: 6, fill: '#3A2A1E' },
  { op: 'polygon', points: [[50, 55], [60, 55], [55, 62]], fill: '#E88080' },
  { op: 'line',  x1: 10, y1: 70, x2: 30, y2: 66, stroke: '#C87F3C', strokeWidth: 1.5 },
  { op: 'text',  x: 60, y: 90, text: '喵', size: 12, align: 'center', color: '#3A2A1E' }
]})
```

**坐标单位是 dp**，不是像素 —— 和 `width`/`height` 一致，换屏幕密度不会跑位。
最好的习惯是把坐标写成「相对边长的比例」（`s = width`，用 `s*0.3` 这类表达式），
这样同一份绘制代码在任意尺寸下都不变形。

指令一览：

| `op` | 必填 | 可选 |
|---|---|---|
| `rect` | `x` `y` `w` `h` | `radius`（圆角）、`fill`、`stroke`、`strokeWidth` |
| `circle` | `cx` `cy` `r` | `fill`、`stroke`、`strokeWidth` |
| `arc` | `x` `y` `w` `h` | `start`（默认 0）、`sweep`（默认 360）、`useCenter`、`fill`、`stroke`、`strokeWidth` |
| `line` | `x1` `y1` `x2` `y2` | `stroke`（或 `fill`）、`strokeWidth` |
| `path` / `polyline` / `polygon` | `points: [[x,y], ...]` | `close`（`polygon` 自动闭合）、`fill`、`stroke`、`strokeWidth` |
| `text` | `x` `y` `text` | `size`（默认 14）、`color`、`bold`、`align`（`left`/`center`/`right`） |

规矩：

- `fill` 和 `stroke` 都可以省，按你给的那个画（两个都省就不画）。同一个图形可以两个都给：
  先填色再描边
- 颜色写法与其它组件一致（`#RRGGBB` / `#AARRGGBB` / `transparent` / 主题 token）
- `arc` 用 `w≠h` 就是椭圆
- `text` 的 `x/y` 是**文字左上角**（不是基线），`align` 控制横向对齐
- 认不出的 `op` 跳过不报错：一个画不出来的图形不会让整页空白

> 宿主只执行**数据**，不接受 JS 绘制回调 —— 插件代码不会进入宿主的绘制流程。
> 这也意味着 `Canvas` 不能画动态自定义路径的复杂动画，能画的就是上表这些。

### 逐帧动画（`Image.frames`）

需要会动的图（帧序列素材、自己算出来的动画帧）用 `frames` 而不是反复改 `src`：

```js
ctx.UI.Image({
  frames: ['file:///.../pet_1.png', 'file:///.../pet_2.png', 'file:///.../pet_3.png'],
  interval: 300,          // 毫秒，默认 480，下限 80
  width: 96, height: 96
})
```

宿主会**先把所有帧解码好再循环切换**。如果用 `setInterval` 反复改 `src`，每一帧都要
重新读盘 + 解码（解码还是异步的），画面会闪、也会拖慢同一页其它部分的渲染。

> 只解 PNG/JPEG 这类静态图。**GIF 动图只显示第一帧** —— 需要动图就自己拆成帧序列。

### 同一个 `ui` 文件，两种容器（`ctx.container`）

插件的界面文件会被**两个容器**渲染：插件面板（点快捷入口进去的那个页），以及桌面浮窗
（`ctx.overlay.show()`）。同一份代码要在两边都站得住，就得知道自己现在在哪儿：

```js
var inOverlay = ctx.container === 'overlay';

return ctx.UI.Column({ padding: inOverlay ? 0 : 6 }, [
  // 浮窗里不要画标题栏/按钮：用户要的是“只有本体”
  inOverlay ? null : ctx.UI.Row({}, [ctx.UI.TextButton({ text: '收回', onClick: recall })]),
  ctx.UI.Image({ src: 'asset://assets/pet.webp', width: size, height: size })
]);
```

| 值 | 场景 |
|---|---|
| `'panel'` | 插件面板（含服务状态/配置/按钮的完整界面） |
| `'overlay'` | 桌面浮窗（在例子里只要有本体） |

⚠ **不要用 `ctx.overlay.isShowing()` 区分身份**：浮窗开着的时候，面板里调它也返回
`true`，于是面板会把自己当成浮窗、把按钮全藏了 —— 用户就再也找不到「收回」入口。
`isShowing()` 只回答“现在桌面上有没有我的浮窗”，不回答“我是谁”。

### ctx 方法全集

```js
// ---- 状态 ----
ctx.useState(key, init)          // → [value, setter]
ctx.useMemo(key, fn, deps)
ctx.useRef(key, init)            // → { current }

// ---- 容器身份 ----
ctx.container                    // 'panel'（插件面板）| 'overlay'（桌面浮窗）

// ---- 配置（需 env）----
ctx.getEnv(key)                  // → 值或 undefined
ctx.setEnv(key, value)           // 立即持久化
ctx.setEnvs({ a: 1, b: 2 })

// ---- 结构化存储（需 env，适合存对象/数组）----
ctx.store.get(key, default)
ctx.store.set(key, value)
ctx.store.remove(key)
ctx.store.keys()                 // → string[]
ctx.store.clear()

// ---- 提示（需 toast）----
ctx.showToast('...')
ctx.reportError(err)             // 在界面弹出错误提示

// ---- 工具调用（需 call_tool，返回 Promise）----
await ctx.callTool('tool_name', { arg: 1 })

// ---- 插件间总线（需 bus，返回 Promise）----
await ctx.bus.publish('topic', payload)      // → { ok, seq }
await ctx.bus.subscribe('topic')             // → { ok, latestSeq }
await ctx.bus.unsubscribe('topic')
await ctx.bus.poll('topic', sinceSeq, limit) // → { ok, messages: [...] }
await ctx.bus.latestSeq('topic')             // → { ok, seq }

// ---- 发起 AI 任务（需 chat_task，返回 Promise）----
await ctx.chat.runTask('总结今天的新闻', { newConversation: true })
// → { ok, conversationId, started }

// ---- 文件操作（需 file，返回 Promise）----
await ctx.readFile('a.txt')                  // → { ok, content, size }（不是纯字符串！）
await ctx.writeFile('a.txt', 'hello')
await ctx.listFiles('sub')
await ctx.moveFile('a.txt', 'sub/b.txt')     // → { ok, path }
await ctx.copyFile('a.txt', 'copy.txt')      // → { ok, path }
await ctx.searchFiles({ dir: '.', ext: 'txt', content: 'keyword' })
                                             // → { ok, count, hits: [{path,name,isDirectory,size}] }
await ctx.zip('folder', 'pack.zip')          // → { ok, path, files, size }
await ctx.unzip('pack.zip', 'out')           // → { ok, path, files }
await ctx.diff('a.txt', 'b.txt', 3)          // → { ok, same, diff }

// ---- 网络（需 http，返回 Promise）----
await ctx.fetch('https://...')                       // GET
await ctx.http({ url, method, headers, body })       // 完整控制

// ---- 服务启停（需 server，仅服务型插件，返回 Promise）----
ctx.serviceControl({ cmd: 'status' })   // → { ok, running, port, requests }
ctx.serviceControl({ cmd: 'start' })    // → { ok, port }
ctx.serviceControl({ cmd: 'stop' })     // → { ok }

// ---- 音频播放（需 audio，**全部同步返回**，不返回 Promise）----
ctx.audio.play(url, { title: '曲名', artist: '作者' })  // 本地绝对路径 或 http(s)（含 m3u8）
ctx.audio.playQueue([{ uri: '/sdcard/a.mp3', title: 'A', artist: '' }, /* ... */], 0)
ctx.audio.pause()
ctx.audio.resume()
ctx.audio.toggle()
ctx.audio.stop()
ctx.audio.next()
ctx.audio.previous()
ctx.audio.seekTo(30000)      // 毫秒
ctx.audio.setVolume(0.8)     // 0..1
ctx.audio.state()            // → { playing, buffering, positionMs, durationMs, volume, error, uri, title, artist, isLive }

// ---- UI 自动化（需 ui；查询类同步返回，动作类返回 Promise）----
ctx.ui.ready()                          // → { ok, running } 无障碍服务是否已开
ctx.ui.snapshot({ maxNodes, maxDepth }) // → { ok, nodes:[...], count, truncated }
ctx.ui.find(selector, limit)            // → { ok, nodes:[...], count }
ctx.ui.foreground()                     // → { ok, package }
await ctx.ui.tap(selector)              // 语义点击 → { ok, via: 'action' | 'gesture', node }
await ctx.ui.tapAt(x, y)                // 坐标点击
await ctx.ui.setText(selector, '文本')
await ctx.ui.scroll(selector, 'down')   // 'down' | 'up'
await ctx.ui.swipe(x1, y1, x2, y2)
await ctx.ui.waitFor(selector, 5000)    // → { ok, node, elapsedMs }
await ctx.ui.back()                     // 还有 home / recents / notifications /
                                        //   quickSettings / power / lock

// ---- 设备与应用（需 system）----
ctx.device.info()                       // → { ok, brand, model, android, sdk, screen, memory, storage, abis }
ctx.device.battery()                    // → { ok, percent, temperature, charging, status }
await ctx.app.list(200)                 // → { ok, apps: [{ package, label, version, system }], count }
await ctx.app.search('微信', 20)        // → 同上，按包名或应用名模糊匹配
await ctx.app.launch('com.tencent.mm')
ctx.app.foreground()                    // 需 **ui** 权限（靠无障碍读窗口）

// ---- 摘要与编码（纯本地计算，无需权限）----
ctx.crypto.hash('sha256', 'abc')        // → { ok, algorithm, hex }；支持 md5/sha1/sha256/sha512
ctx.crypto.base64('encode', 'abc')      // 'encode' | 'decode' → { ok, text }

// ---- 剪贴板（需 clipboard）----
ctx.copy('text')
ctx.paste()                      // → { ok, text }

// ---- 通知（需 notify）----
ctx.notify('标题', '内容')

// ---- 文件（需 file）----
ctx.readFile('note.txt')                       // → { ok, content, size }
ctx.writeFile('note.txt', 'hello')             // 沙箱内相对路径
ctx.listFiles('')                              // → { ok, files: [] }
ctx.pickFile({ mime: ['text/plain'] })         // → { ok, name, content } 或 { cancelled: true }
ctx.saveFile('out.txt', 'content')             // → { ok, name }
ctx.pickImage()                                // → { ok, data: 'data:image/...' }
```

### 文件沙箱

`readFile` / `writeFile` / `listFiles` 只能访问 **插件自己的沙箱目录**：

```
<app私有目录>/openx/plugin-files/<你的插件id>/
```

用**相对路径**（如 `note.txt`、`data/log.json`）。传绝对路径或 `..` 会被拒绝。

`pickFile` / `saveFile` 走系统选择器，用户主动选择的文件不受沙箱限制。

### 异步注意

`callTool` / `http` / `fetch` / `pickFile` / `saveFile` / `pickImage` **返回 Promise**，
在 UI 事件里用 `await`：

```js
async function handleFetch() {
  const res = await ctx.fetch('https://api.example.com/data');
  if (res.ok) {
    setData(JSON.parse(res.body));
  } else {
    ctx.showToast('请求失败：' + res.error);
  }
}
```

⚠ 这些调用会阻塞插件自己的 JS 线程直到返回（底层是同步桥）。慢请求期间界面会**停止响应**，
所以别在渲染期间直接调用，只放在事件处理里。

⚠ 更要命的是：**action 派发期间宿主持有该插件的 session 锁**，`ctx.http` 又在事件回调里同步
阻塞，于是慢请求会把整个插件面板（连开/关、切页都）一起冻住。插件 HTTP 超时已放宽到
300 秒，但「慢」本身不会变快 —— 慢接口请用 `setTimeout(function () { ... }, 0)` 把请求挪到
锁外再发（详见 [6.1](#61-宿主运行时限制踩坑高发区先看这里) 与 [第 10 节](#10-音频播放) 踩坑）。

`ctx.audio.*` 是**例外：全部同步立即返回**（宿主只把命令 post 到播放线程），不阻塞、不需 `await`。

## 6.1 宿主运行时限制（**踩坑高发区，先看这里**）

插件跑在宿主自带的 QuickJS 里，**不是浏览器，也不是完整 Node**。
以下差异会直接让代码报错或静默失效。

### 6.1.1 没有 `useEffect`；定时器能驱动重渲染，但不能重复注册

**没有** React 的 `useEffect`、`useLayoutEffect`；但宿主提供按 key 保存状态的
`ctx.useState`、`ctx.useMemo`、`ctx.useRef`（见第 4 节）。
`Screen()` 会反复调用，这些 API 不依赖 React 的 Hook 调用顺序。

宿主**在三种时刻**调用你的 `Screen()`：
1. 打开面板时
2. 事件回调触发后（`onClick` 等走action 派发）
3. `setInterval` / `setTimeout` 回调执行完之后

所以这样写**会**每秒刷新：

```js
// ✅ 有效：定时器回调执行后宿主会重新调用 Screen()
setInterval(function () { setNow(new Date()); }, 1000);
```

⚠ 但 `Screen()` 会在上述三种时刻**反复执行**。若把 `setInterval` 直接写在函数体里，
每次渲染都会**再注册一个定时器**，回调越跑越多、界面越来越卡：

```js
// ❌ 错误：每次渲染都注册一个新的 interval，1秒后会有 N 个回调同时跑
function Screen(ctx) {
  const [now, setNow] = ctx.useState('now', new Date());
  setInterval(function () { setNow(new Date()); }, 1000);   // 每次进来都加一个
  return ctx.UI.Text({ text: now.toLocaleTimeString() });
}
```

**正确写法**：用一个只会从初始值变一次的 state 当「已启动」标记，注册逻辑只在首帧跑：

```js
function Screen(ctx) {
  const [now, setNow] = ctx.useState('now', new Date());
  const [booted, setBooted] = ctx.useState('booted', false);
  if (!booted) {                 // 只有首帧 booted=false，后续都是true
    setInterval(function () { setNow(new Date()); }, 1000);
    setBooted(true);
  }
  return ctx.UI.Text({ text: now.toLocaleTimeString() });
}
```

⚠ 定时器回调使用注册时捕获的闭包；**不要依赖其中捕获的旧 state 值**。
要更新多个状态可以用函数式 setter，或保存 setter 引用；setter 按 key 操作宿主状态：

```js
var __setNow;                     // 模块级：跨渲染稳定
function Screen(ctx) {
  const [now, setNow] = ctx.useState('now', new Date());
  const [booted, setBooted] = ctx.useState('booted', false);
  if (!booted) {
    __setNow = setNow;            // 首帧存下setter，后续定时器用
    setInterval(function () { __setNow(new Date()); }, 1000);
    setBooted(true);
  }
  return ctx.UI.Text({ text: now.toLocaleTimeString() });
}
```

⚠ **别忘了 `clearInterval`**：面板关闭时宿主会销毁引擎、定时器随之失效，
但同一界面内重复启动的操作（如反复点「开始」）需要自己清理旧定时器：

```js
var __timerId = null;
function start() {
  if (__timerId !== null) clearInterval(__timerId);   // 先清旧的
  __timerId = setInterval(function () { ... }, 1000);
}
```

### 6.1.2 `Intl` 只有精简版（宿主 polyfill）

宿主的 QuickJS **没有编译 ECMA-402**，宿主注入了一层**精简 polyfill**。
可用：

| API | 支持范围 |
|---|---|
| `Intl.DateTimeFormat` | `dateStyle` / `timeStyle` / `year` / `month` / `day` / `hour` / `minute` / `second` / `weekday` / `hour12` / `timeZone` / `timeZoneName` |
| `Intl.NumberFormat` | 小数位 + 千分位 |

**不可用（调用即抛 `TypeError`）**：
`Intl.Collator` / `PluralRules` / `RelativeTimeFormat` / `ListFormat` / `Segmenter`

⚠ **时区**：`timeZone` 只认 `'UTC'` 和设备本地时区（`'local'`），
其它 IANA 名（如 `'Asia/Shanghai'`）会抛 **RangeError**。
宿主容器里没有 IANA 时区数据库，给错时区比报错更危险，所以直接报错。

⚠ 排序别用 `localeCompare`（依赖 `Collator`，不可靠）：

```js
list.sort(function (a, b) { return a < b ? -1 : 1; });   // ✅
```

⚠ `formatToParts` 只返回单个 literal，**不是规范行为**，别拿它做结构化解析。

### 6.1.3 `Date` 没有 `Intl` 支撑的本地化输出

`toLocaleDateString` / `toLocaleTimeString` 可用（走宿主实现），
但不带时区数据库，只按设备本地时区格式化。

### 6.1.4 工具侧（`main.js`）没有 `ctx`

`ctx` **在 UI 和服务脚本中存在，工具入口 `main.js` 没有**。`main.js` 是工具侧运行时，
拿不到 `ctx`、也没有 UI 组件。工具里调`ctx.xxx()` 会直接抛异常。

工具侧能用的：宿主注入的 `$ptools` / `$callTool`（见第 3 节）、
标准 JS、以及本节的 `Intl` polyfill。

### 6.1.5 其它缺失

- 没有浏览器原生的完整 `fetch` 实现；UI 侧 `ctx.http` / `ctx.fetch` 返回 Promise（宿主异步桥），服务侧 `ctx.http` 是同步调用，见第 9 节
- 没有 `WebSocket`、`Worker`、`localStorage`
- 没有 `Intl` 之外的 ECMA-402 附属对象
- **音频播放限制已解除（2.7.4）**：宿主内置 ExoPlayer，声明 `audio` 权限即可播放本地音频
  与网络电台流（含 HLS `.m3u8`），界面用 `AudioBar`，见 [第 10 节](#10-音频播放)。
  （旧的「不支持 `audio` 组件」说法已作废。）

## 8. 常见问题

### 界面一片空白 / 显示"插件没有返回界面内容"

`Screen()` 返回了 `null` / `undefined`。检查入口函数有没有 `return`。

### 报"未找到界面入口"

入口写法不对。确认三者之一：

```js
module.exports = Screen;    // 或
exports.default = Screen;   // 或
function Screen(ctx) {}     // 全局函数
```

### 报"ui 入口文件不存在"

`plugin.json` 的 `ui` 字段写对了，但文件没打进包。压缩时容易被 `.gitignore` 或
`-x` 规则漏掉子目录，检查 zip 内容。

### 禁用了插件但工具还在

工具名前缀不一致。同一个插件的所有工具必须用**同一个下划线前缀**，见 [第 3 节](#3-注册工具mainjs)。

### 点了快捷项没反应

按 `action` 查对应字段是否非空：

| `action` | 必需字段 | 缺失时表现 |
|---|---|---|
| `openUi` | `ui` | 点了没反应。只有工具的插件没有界面，快捷项应改用 `prompt` |
| `openUrl` | `url` | 提示「该快捷项未配置网址」 |
| `prompt`（默认） | `prompt` | 提示「该快捷项未配置提示词」 |

### 状态没同步 / 输入框打不出字

`TextField` 的 `value` 必须绑定 `useState` 的值：

```js
const [name, setName] = ctx.useState('name', '');
ctx.UI.TextField({ value: name, onValueChange: setName })
```

只写 `onValueChange` 不写 `value` 会导致输入不显示（组件是受控的）。

### 切 Tab 后输入框还是上一个 Tab 的内容

宿主按「树中位置」复用输入框的本地状态（光标、正在输入的内容）。若两个 Tab 的
`TextField` 落在同一位置（最常见：各自 Tab 的第一个子节点），切 Tab 时状态会被沿用，
看起来就是内容没变。

给每个输入框传一个**唯一且稳定**的 `key`，宿主就会把它当作不同的输入框重新接管：

```js
ctx.UI.TextField({ key: 'radioKw', value: radioKw, onValueChange: setRadioKw })
ctx.UI.TextField({ key: 'scanDir', value: scanDir, onValueChange: setScanDir })
```

`key` 只用在同一位置会「换身份」的输入框上（不同 Tab、条件渲染的分支）。
同一输入框的 key 不要随内容变化，否则每次输入都会被重置。

### 网络图显示"网络图需要 http 权限"

`Image` 加载 http(s) 图片需要 `http` 权限，没声明就不发请求。
本地图片路径还需要 `file` 权限。

### 异步调用后界面卡住

`ctx.fetch` / `ctx.callTool` 会阻塞插件 JS 线程。别在渲染函数体里调用，
只放在事件处理里，并注意超时（HTTP 默认 60s）。

### 组件不支持

对照 [第 5 节](#5-组件参考) 的组件表。不支持时会显示替代建议；
确实需要的组件可以在项目里提需求。

function Screen(ctx) {
  const [name, setName] = ctx.useState('name', '');
  const [count, setCount] = ctx.useState('count', 0);

  return ctx.UI.Column({ padding: 16 }, [
    ctx.UI.Text({ text: '示例面板', fontSize: 20, bold: true }),
    ctx.UI.Spacer({ height: 12 }),

    ctx.UI.Card({ cornerRadius: 12 }, [

        label: '你的名字', placeholder: '输入后点保存'

      ctx.UI.Spacer({ height: 10 }),
      ctx.UI.Button({ text: '保存', onClick: handleSave }),
      saved ? ctx.UI.Text({ text: '上次保存：' + saved, fontSize: 11, color: 'success' })
            : ctx.UI.Spacer({ height: 0 })
    ]),

    ctx.UI.Spacer({ height: 12 }),

    ctx.UI.Card({ cornerRadius: 12 }, [
      ctx.UI.Row({ horizontalArrangement: 'spaceBetween', fillMaxWidth: true }, [
        ctx.UI.Text({ text: '启用功能', fontSize: 14 }),
        ctx.UI.Switch({ checked: enabled, onCheckedChange: setEnabled })
      ]),
      ctx.UI.Spacer({ height: 8 }),
      ctx.UI.Row({ horizontalArrangement: 'spacedBy', verticalAlignment: 'center' }, [
        ctx.UI.Button({ text: '+1', onClick: () => setCount(count + 1) }),
        ctx.UI.Button({ text: '-1', onClick: () => setCount(count - 1) }),
        ctx.UI.Text({ text: '当前：' + count, fontSize: 16, bold: true, color: 'primary' })
      ])
    ]),

    ctx.UI.Spacer({ height: 12 }),
    enabled
      ? ctx.UI.Card({ background: 'primary' }, [
          ctx.UI.Text({ text: '功能已启用', color: 'onprimary', bold: true })
        ])
      : ctx.UI.Text({ text: '（功能已关闭）', color: 'textsecondary' })
  ]);
}

## 9. 服务型插件（本地网关）

> 2.6.7 新增。适用于「本地 HTTP 网关」类插件：启动后在后台常驻，监听一个本地端口，
> 对外提供 API（如 OpenAI 兼容接口），其他工具通过 `http://127.0.0.1:<port>` 访问。
> 典型场景：免费模型网关、本地 API 转发器、Mock 服务器。

### 用户从哪里启动它：插件详情页的「插件配置」

插件详情页分两个页签，位置是固定的，写插件时要清楚用户会去哪里找：

| 页签 | 装什么 |
|---|---|
| **插件管理** | 只读信息：ID / 版本 / 作者 / 目录 / 入口 / 界面脚本 / 权限 / 注册的工具 / 快捷入口 / 兼容性诊断 |
| **插件配置** | **后台脚本的入口**：服务状态（运行中 · 监听 `127.0.0.1:<端口>`）、启动 / 停止按钮、定时任务清单 |

所以：**声明了 `service` 或 `schedule`，用户就是在「插件配置」页启动它**。
没有 `service` / `schedule` 时不会有后台启动入口；但只要清单声明了 `settings`，
纯工具或纯界面插件也能在「插件配置」页看到宿主渲染的配置项（见第 2 节）。

> 这页既能管理后台脚本，也能渲染清单 `settings`。需要复杂业务交互时再在面板里提供表单。

#### 两种后台脚本：宿主开端口 vs 脚本自己进程

声明 `service` 只是要求「有个后台脚本」。它干什么取决于你申不申请 `server` 权限：

| | 申请了 `server` | 没申请 `server` |
|---|---|---|
| 宿主行为 | 给它绑一个 HTTP 端口，外部请求进 `handleRequest` | **不绑端口**，只跑脚本的 `onStart` / `onStop` / `onSchedule` |
| 适合 | 纯 JS 写的本地 API | 后台是**容器里的常驻进程**（JVM / Node / 二进制），脚本用 [`ctx.exec`](#194-服务运行时能用的-ctx) 管它的生死 |
| 配置页 | 「启动服务 / 停止服务」 | 「启动后台脚本 / 停止后台脚本」 |

后一种正是「插件把一堆外部程序打包进来、让用户一键开关」的形态：脚本本身很薄，
真正的服务在容器里，宿主只需要负责启停。

### 与普通插件的区别

| | 工具型（main.js） | 界面型（ui/*.js） | **服务型（service/*.js）** |
|---|---|---|---|
| 生命周期 | AI 调用时执行 | 界面打开期间 | **用户在「插件配置」页点启动后常驻**，界面关了也活着 |
| 引擎 | 每次调用新建 | 界面绑定 | **独立引擎，启动到停止** |
| 触发方式 | AI 工具调用 | 用户点击 | **外部 HTTP 请求** |
| 端口 | — | — | **监听 127.0.0.1（仅本机）** |

### plugin.json 声明

```json
{
  "id": "my.gateway",
  "name": "我的网关",
  "version": "1.0.0",
  "main": "main.js",
  "ui": "ui/panel.ui.js",
  "service": "service/gateway.js",
  "port": 18899,
  "permissions": ["http", "env", "server"],
  "quickActions": [
    { "label": "打开面板", "action": "openUi", "icon": "router" },
    { "label": "浏览器打开管理页", "action": "openUrl", "url": "http://127.0.0.1:18899/", "icon": "open_in_new" }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `service` | 服务脚本路径。声明后插件详情页的「插件配置」页签出现启动 / 停止按钮 |
| `port` | 期望端口。被占用自动顺延 +1（最多试 10 个），实际端口经 `onStart(info).port` 告知 |
| `server` 权限 | **仅在要宿主监听本地 HTTP 端口时需要**。只需 `onStart` / `onStop` / `onSchedule`、或由 `ctx.exec` 管理容器进程的服务脚本，不必申请；`ctx.serviceControl` 则需要 `server` 权限 |

> `main.js` / `ui` 可与 `service` 共存：一个插件可以既有 AI 工具、又有面板、又有网关，
> 三者跑在**不同引擎**里，经 `ctx.store`（落盘 env）共享状态。

### 服务脚本契约（service/*.js）

```js
'use strict';

// ---- 生命周期（可选但建议都写）----

/** 启动回调：info.port = 实际监听端口（可能因占用顺延过） */
exports.onStart = function (info) {
    ctx.log('网关已启动：' + info.port);
};

/** 停止回调：做清理（统计落盘等） */
exports.onStop = function () {
    ctx.log('网关已停止');
};

// ---- 请求处理（必需）----

/**
 * 每个进入端口的 HTTP 请求调用一次。
 * req = { method, path, query, headers, body }
 *
 * 返回值两种形状：
 * ① 普通响应：{ status, headers, body }
 * ② 流式代理：{ stream: true, upstream: { url, method, headers, body } }
 *    —— 宿主直接把 upstream 的响应字节（SSE 逐帧）原样转发给客户端，
 *       JS 只负责拼上游请求（协议转换），不经手流数据。
 */
exports.handleRequest = function (req) {
    // CORS 预检
    if (req.method === 'OPTIONS') {
        return { status: 204, headers: corsHeaders(), body: '' };
    }

    // GET /v1/models → 模型清单
    if (req.method === 'GET' && req.path === '/v1/models') {
        return {
            status: 200,
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify({ object: 'list', data: [/* ... */] })
        };
    }

    // POST /v1/chat/completions → 流式转发上游
    if (req.method === 'POST' && req.path === '/v1/chat/completions') {
        var body = JSON.parse(req.body || '{}');
        if (!body.model) {
            return { status: 400, headers: {}, body: '{"error":"missing model"}' };
        }
        if (body.stream === true) {
            // ② 流式：宿主搬运字节，不占 JS 线程
            return {
                stream: true,
                upstream: {
                    url: 'https://upstream.example/v1/chat/completions',
                    method: 'POST',
                    headers: { 'Content-Type': 'application/json', 'Authorization': 'Bearer xxx' },
                    body: JSON.stringify(body)
                }
            };
        }
        // ① 非流式：同步 ctx.http 转发（需 http 权限）
        var resp = ctx.http({
            url: 'https://upstream.example/v1/chat/completions',
            method: 'POST',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify(body),
            timeout: 120000
        });
        var parsed = JSON.parse(resp);
        return parsed.ok
            ? { status: parsed.status, headers: {}, body: parsed.body }
            : { status: 502, headers: {}, body: JSON.stringify({ error: parsed.error }) };
    }

    return { status: 404, headers: {}, body: '{"error":"not found"}' };
};

function corsHeaders() {
    return {
        'Access-Control-Allow-Origin': '*',
        'Access-Control-Allow-Methods': 'GET, POST, OPTIONS',
        'Access-Control-Allow-Headers': 'Authorization, Content-Type'
    };
}
```

### ctx API（服务脚本内可用）

服务引擎里 `ctx` 是精简版（无 UI 相关）：

```js
ctx.getEnv(key) / ctx.setEnv(key, value) / ctx.setEnvs(map)   // 需 env 权限
ctx.store.get / set / remove / keys / clear                    // 需 env 权限
ctx.http({ url, method, headers, body, timeout })             // 需 http 权限，同步阻塞
ctx.fetch(url, options)                                       // 同上
ctx.log(...)                                                  // 输出到日志（无 toast）
ctx.reportError(err)                                          // 错误记日志
```

⚠ **`ctx.http` 是同步的**，且服务引擎是单线程：一个慢请求会阻塞后续请求的**处理**
（但不阻塞已在搬运中的流——流由宿主线程搬运）。转发类网关尽量用 `stream: true`。

### 流式代理细节

- 上游响应的 `content-type` 透传（`text/event-stream` 保持原样）
- 8KB 缓冲逐块搬运，SSE 帧不解析不缓存
- 上游空闲超时 900 秒（对齐长思考模型的静默期）
- 上游断开 / 超时 → 连接直接结束（客户端表现为流关闭）

### 状态共享（服务 ↔ 面板）

服务引擎与 UI 引擎**不共享内存**，经 `ctx.store` 落盘共享：

```js
// service/gateway.js 里每次请求后（节流写）
ctx.store.set('gateway_stats', { running: true, port: 18899, requests: 42 });

// ui/panel.ui.js 里渲染时读
var stats = ctx.store.get('gateway_stats', {}) || {};
```

env 文件路径：`<app私有目录>/openx/pluginEnv/<插件id>.json`（两个引擎读写同一份）。

### 启停与调试

- **启动**：插件管理 → 点插件卡片 → 详情页 **「插件配置」** 页签 → 启动按钮。启动期间按钮变为
  「正在启动…」并禁用，状态块显示 `正在启动…`；成功后卡片显示绿色 `服务:<端口>` 徽标，
  配置页状态变为 `运行中 · 监听 127.0.0.1:<端口>`。
- **失败**：`onStart` 抛异常时状态块显示 `启动失败`（红色），页面内直接给出错误原因，
  同时弹 Toast。原因可能是命令非零退出、没有完成标记，或服务端口健康检查不通——
  排查时先看插件日志，再看容器里的服务日志。
- **停止**：同一个页签里的按钮（运行中时会变红）。
- **面板内控制（2.6.9 新增）**：UI 面板脚本可用 `ctx.serviceControl({cmd})` 启停/查询服务，
  需 `server` 权限。启停成功后插件管理页与卡片状态自动同步刷新。

  ```js
  ctx.serviceControl({ cmd: 'status' }).then(function (res) {
      // res = { ok: true, running: true, port: 18899, requests: 42 }
  });
  ctx.serviceControl({ cmd: 'start' }).then(function (r) { /* r = {ok:true, port:18899} */ });
  ctx.serviceControl({ cmd: 'stop' }).then(function (r) { /* r = {ok:true} */ });
  ```
- **验证**：浏览器访问 `http://127.0.0.1:<port>/`，或 `curl http://127.0.0.1:<port>/v1/models`。
- **日志**：`ctx.log` 输出到应用日志（容器内 `~/.openx/logs/` 或日志页）。

### 限制与安全

- **只绑 127.0.0.1**：局域网设备无法访问（当前版本不做 0.0.0.0 绑定）。
- 请求头上限 64KB，body 上限 8MB，超出拒绝。
- `server` 是危险权限：声明后界面顶部有橙色提示条。
- 服务随 App 进程存活：App 被杀服务即停（下次手动启动）。

## 10. 音频播放

宿主内置播放器（ExoPlayer / media3），插件可以播放**本地音频文件**和**网络电台流**（含 HLS `.m3u8`）。

### 10.1 声明权限

```json
{
  "id": "openx.my-player",
  "name": "我的播放器",
  "version": "1.0.0",
  "description": "播放本地音乐与网络电台",
  "main": "main.js",
  "ui": "ui/panel.ui.js",
  "apiVersion": "1.0.0",
  "permissions": ["audio"]
}
```

`audio` 不算危险权限（不涉及用户数据外泄），所以界面顶部**不会**出现橙色提示条。
但它能在后台持续出声——请在 `description` 里写明，让用户有预期。

### 10.2 播放

```js
// 网络电台（http/https，含 .m3u8）
ctx.audio.play('https://example.com/stream.mp3', { title: '某电台', artist: 'France' });

// 本地文件：传绝对路径
ctx.audio.play('/mnt/sdcard/Music/song.mp3', { title: '歌名' });

// 整单播放（2.7.5 新增）：只有传了队列，通知栏/媒体卡片的上下曲才真正能切歌
ctx.audio.playQueue([
  { uri: '/mnt/sdcard/Music/a.mp3', title: 'A', artist: '' },
  { uri: '/mnt/sdcard/Music/b.mp3', title: 'B', artist: '' }
], 0);   // 第二个参数是起始下标
```

其余方法：

```js
ctx.audio.pause();
ctx.audio.resume();
ctx.audio.toggle();
ctx.audio.stop();
ctx.audio.next();              // 下一曲（队列只有一首时重播当前曲）
ctx.audio.previous();          // 上一曲
ctx.audio.seekTo(30000);       // 毫秒
ctx.audio.setVolume(0.8);      // 0..1
ctx.audio.state();             // 读当前状态快照
```

**这些方法全部同步返回**（不是 Promise），因为宿主只是把命令 post 到播放线程就返回，
不会阻塞插件。`state()` 返回：

```js
{
  playing: false,      // 是否在播放
  buffering: true,     // 是否缓冲中
  positionMs: 0,       // 播放位置
  durationMs: 0,       // 总时长（直播流为 0）
  volume: 1.0,
  error: null,         // 出错时的原因
  uri: '...', title: '...', artist: '...',
  isLive: false        // 是否直播流
}
```

### 10.3 播放条组件

```js
ctx.UI.AudioBar({ showVolume: true })
```

`AudioBar` 由**宿主渲染**，内置进度刷新、音量滑杆、上一曲/播放暂停/下一曲/停止按钮
（2.7.5 起带上下曲；切歌仍取决于是否用 `playQueue` 建了队列）。
它**不接 `onClick`**——按钮直接操作宿主播放器，所以任何插件页面上的播放条
都反映同一份真实状态。

属性：

| 属性 | 默认 | 说明 |
|---|---|---|
| `showVolume` | `false` | 是否显示音量滑杆 |
| `compact` | `false` | 隐藏进度条与时间 |

> 直播流没有有意义的时长，播放条会自动隐藏进度条。

### 10.4 行为说明

- **切走 App 继续播**：播放时宿主会拉起前台服务（通知栏出现媒体控制条），
  进程保持前台优先级，所以切到别的 App 音乐不会断。
- **通知栏控制**：通知条有上一曲/播放暂停/下一曲/停止，带进度、时长与大图标，
  并声明 `CATEGORY_TRANSPORT`（2.7.5：部分 ROM 如 OriginOS 靠它才渲染控制区）；
  同时支持耳机按键与蓝牙控制。
- **上下曲需要队列**：`ctx.audio.play()` 是单曲（队列长度 1），点上下曲只是重播当前曲；
  要真正切歌请用 `ctx.audio.playQueue([...], startIndex)`。
- **停止即撤通知**：`ctx.audio.stop()` 后前台通知会被撤掉，不占通知栏。
- **缓冲超时**：直播流长时间拉不到数据会报「缓冲超时，这个流可能已失效」，
  不会一直转圈。电台流经常失效，插件最好处理 `state().error` 并提示用户。
- **跟随重定向**：电台站大量使用 301/302 跳转，宿主已配置自动跟随。

### 10.5 踩坑

- **别在 `onClick` 里 `await` 别的慢接口**：`ctx.http` 是同步阻塞实现，
  在 action 派发里 await 会占住插件 session 锁，面板僵死。
  用 `setTimeout(() => { ... }, 0)` 把网络请求挪到锁外。
- **`ctx.audio` 不会被 `useState` 持久化**：播放状态在宿主里，插件重渲染不影响播放。
  想在界面上显示播放状态，用 `ctx.audio.state()`，或直接放一个 `AudioBar`。
- **插件被禁用/卸载时应该停掉播放**（`ctx.audio.stop()`），否则会一直响。

## 11. UI 自动化（ctx.ui）

插件用宿主已有的无障碍服务，做「读屏 → 找到控件 → 点它」这类事。
底层不新开服务，就是你平时在「设置 > 应用权限授权 > 无障碍」里给 OpenX 开的那个。

### 11.1 声明权限与前置条件

```json
{ "permissions": ["ui"] }
```

`ui` 是**危险权限**，安装确认页会红字提示，界面顶部还会常驻橙色警告条——这权限能读到
其它应用的全部可见文字，属于插件能拿的最大权限，不打算用就别声明。

用户没开无障碍时所有 `ctx.ui.*` 都返回 `{ ok: false, error: "无障碍服务未运行…" }`，
不会抛异常。写界面时先探一下：

```js
const ready = ctx.ui.ready();
if (!ready.running) {
  return ctx.UI.Column({}, [
    ctx.UI.Text({ text: '需要无障碍服务：设置 > 应用权限授权 > 无障碍 > OpenX' })
  ]);
}
```

### 11.2 选择器

除了 `ready / snapshot / tapAt / swipe / back…` 之外，动作都收一个**选择器对象**：

```js
{ text: '登录' }              // 精确匹配 text 或 contentDescription
{ textContains: '登' }        // 包含匹配（同样看 text 和 desc）
{ id: 'com.foo:id/btn' }      // 完整资源 id
{ id: 'btn' }                 // 也可以只给最后一段
{ className: 'Button' }       // 简名或全名都行
{ desc: '搜索' }              // 只匹配 contentDescription
{ clickable: true, index: 1 } // 第二个可点控件
```

多个字段是 **AND**；`index` 用于「同名控件点第 N 个」（从 0 开始）。

> `text` 会同时看 `text` 和 `contentDescription`：界面上"看到的字"经常挂在描述上
> （图标按钮尤其如此），只认 text 会让插件反复找不到明明在屏幕上的控件。

### 11.3 查询（同步返回）

```js
// 整棵界面树：扁平数组 + parent 索引，字段是短名（cls/b/clk/ed/scr…）
const page = ctx.ui.snapshot({ maxNodes: 400, maxDepth: 40 });
// → { ok, count, truncated, nodes: [
//     { i:0, p:-1, d:0, cls:'FrameLayout', b:[0,0,1080,2400] },
//     { i:1, p:0, d:1, cls:'TextView', text:'设置', b:[0,100,500,160], clk:true,
//       id:'com.android.settings:id/title' } ] }

// 只取关心的节点
const hits = ctx.ui.find({ textContains: '设置' }, 5);
// → { ok, count, nodes: [...] }

// 当前前台应用（读窗口拿包名）
const fg = ctx.ui.foreground();  // → { ok, package: 'com.tencent.mm' }
```

为什么扁平化：一份真实应用的界面树常有几百个节点，嵌套 JSON 在 QuickJS 里展开更慢；
带 `p`（parent 索引）后你可以自由重建树，只渲染关心的分支。字段名用短名同理，
`cls` 比 `className` 每节点省 7 字节。

`maxNodes` 默认 400、上限 2000。超了会置 `truncated: true` 并停止遍历，
不会把面板卡死。

### 11.4 动作（返回 Promise）

```js
await ctx.ui.tap({ text: '确定' });        // → { ok, via:'action'|'gesture', node }
await ctx.ui.tapAt(540, 1200);             // 坐标点击（上面那招不灵时的退路）
await ctx.ui.setText({ id: 'search' }, '关键词');
await ctx.ui.scroll({ scrollable: true }, 'down');   // 'down' | 'up'
await ctx.ui.swipe(540, 1800, 540, 600);
await ctx.ui.waitFor({ text: '加载完成' }, 5000);    // → { ok, node, elapsedMs }
await ctx.ui.back();   // home / recents / notifications / quickSettings / power / lock
```

`tap` 的 `via` 值得留意：`action` 表示走无障碍语义点击（稳），
`gesture` 表示语义点击失败、退化成坐标手势（界面滚动后就可能点偏）。

### 11.5 完整例子：打开设置里的 WLAN 页

```js
async function gotoWlan() {
  const ready = ctx.ui.ready();
  if (!ready.running) return { ok: false, error: '请先开启无障碍服务' };

  await ctx.app.launch('com.android.settings');
  await ctx.ui.waitFor({ textContains: 'WLAN' }, 5000);
  const r = await ctx.ui.tap({ textContains: 'WLAN' });
  if (!r.ok) return r;

  await ctx.ui.waitFor({ textContains: '已连接' }, 5000);
  return { ok: true };
}
```

### 11.6 限制

- **一次只返回一屏**：无障碍读的是当前窗口，滚动列表里的离屏项拿不到。要翻页就
  `scroll` 后再 `snapshot`。
- **`find` 只返回可见节点**：屏幕外节点点了没意义，滚动列表里又常有几十个重复控件，
  混进结果只会误导你。
- **`waitFor` 最长 30 秒**：它是同步轮询（每 200ms 一次），期间插件 JS 线程被占住，
  面板不会响应别的点击。别在 `onClick` 里连续 `await` 好几个 `waitFor`。
- **悬浮窗/画中画应用**：无障碍可能读到多个窗口，跨窗口节点会带 `pkg` 字段区分。

## 12. 设备与应用信息

### 12.1 权限

```json
{ "permissions": ["system"] }
```

`system` 是只读权限，不弹红字，但界面顶部仍会列出来——应用列表有一定指纹价值，如实告知。

### 12.2 设备

```js
const dev = ctx.device.info();
// → { ok, brand, manufacturer, model, device, android, sdk, abis: [],
//     screen: { width, height, densityDpi, density },
//     memory: { totalBytes, freeBytes, maxBytes },
//     storage: { totalBytes, freeBytes } }

const bat = ctx.device.battery();
// → { ok, percent: 87, temperature: 31.5, charging: false, status: '放电中' }
```

电池故意放在 `device` 而不是 `ui` 下：读电量不需要无障碍，挂在 `ui` 下会让只想看电量的
插件被迫申请读屏权限。

### 12.3 实时状态

要一次拿到「这台设备现在怎么样」，用 `stats()`：

```js
const s = ctx.device.stats();
// → { ok,
//     cpu:     { usage: 23.5, freqMax: 2400000, cores: 8, freqs: [1800000, 1600000, ...] },
//     memory:  { totalBytes, availBytes, usedBytes, usedPercent,
//                thresholdBytes, lowMemory, appPssBytes },
//     storage: { totalBytes, freeBytes, usedBytes, usedPercent },
//     uptimeMs: 3841200000,
//     battery: { percent: 76, temperature: 31.2, charging: false } }
```

`memory` 和 `ctx.device.info()` 里那个**不是一回事**：`info()` 的 `memory` 取自
`Runtime.totalMemory()`，那是 **JVM 堆**，跟整台设备的内存占用没关系。`stats()` 用
`ActivityManager.MemoryInfo` 取系统级数据，另外用 PSS 给出本进程真实占用（`appPssBytes`）。
做内存监控一律用 `stats()`。

`cpu.usage` 靠**两次采样求差**：宿主缓存上一轮 `/proc/stat` 的 ticks，所以这个值反映的是
两次调用之间的平均占用。进程内第一次调用没有前值，会自采样一次、多花约 80ms。
推荐 1~2 秒轮询一次。

> **`cpu.usage` 在 Android 8.0+ 真机上基本恒为 `-1`（读不到）**：系统从 8.0 起用 SELinux
> 给 `/proc/stat` 打了 `proc_stat` 标签，普通 App 读不到，`readCpuTicks()` 返回 null，
> 宿主只能回 `-1`。这是系统限制，不是宿主 bug，除 root/关 SELinux 无解。
> 要做“CPU 负载”类指标，改用**频率占最高频率的比例**：`cpu.freqs` 求平均，除以 `cpu.freqMax`。

`cpu.freqs` 是逐核当前频率（kHz）。部分机型/核心读不到 `scaling_cur_freq`，读不到的
直接跳过，数组长度可能小于 `cores`。`cpu.freqMax` 是各核频率上限的最大值（kHz，
读不到为 0），用它当分母算频率负载比例。

### 12.4 应用

```js
const all = await ctx.app.list(200);
// → { ok, count, truncated, apps: [{ package, label, version, system }] }

const hit = await ctx.app.search('微信', 20);   // 包名或应用名模糊匹配
await ctx.app.launch('com.tencent.mm');        // → { ok }
```

`list` 只返回**有启动入口**的应用（能在桌面点开的那些），系统组件不会混进来。
默认上限 200，最多 500，超了置 `truncated: true`。

### 12.5 摘要与编码

不需要任何权限，纯本地计算：

```js
ctx.crypto.hash('sha256', 'abc');       // → { ok, algorithm: 'SHA-256', hex: '...' }
ctx.crypto.hash('md5', 'abc');          // 还支持 sha1 / sha512
ctx.crypto.base64('encode', '中文');     // → { ok, text: '5Lit5paH' }
ctx.crypto.base64('decode', '5Lit5paH'); // → { ok, text: '中文' }
```

### 12.6 踩坑

- **`ctx.app.list()` 是异步的**：枚举几百个包并读取应用名要上百毫秒，别在渲染函数里
  直接调（渲染函数每帧都会跑）。放进 `ctx.useMemo` 或事件回调里。
- **`ctx.app.launch` 不等于启动成功**：它只保证 Intent 发出去了。目标应用是否真的起来，
  用 `ctx.ui.waitFor({ package: '目标包名' })` 或 `ctx.ui.foreground()` 确认。
- **`ctx.app.foreground()` 要 `ui` 权限**：它靠无障碍读活动窗口，不是包管理器能问出来的。
- **`ctx.device.stats()` 首次调用慢约 80ms**：CPU 使用率要两次采样求差，首次没有前值会
  自采样一次。别在界面首帧同步调用，放进 `ctx.useMemo` 或定时器里。

## 13. 聊天钩子（Hook）

钩子让插件**参与聊天流程**，而不只是"在旁边看和点"：发消息前改写它、看 AI 的完整回复、
在工具执行前后插手。这是插件系统里权限最大、也最容易把宿主搞坏的一组能力。

### 13.1 声明权限

```json
{ "permissions": ["hook"] }
```

`hook` 是**危险权限**：`onBeforeSend` 能看到并改写你发出的每一条消息，
`onAfterReply` / `onAfterTool` 能看到 AI 的完整回复与工具输出（可能含隐私内容）。
没声明这个权限的插件，写了钩子也不会生效（宿主只记一条日志）。

### 13.2 写法

钩子和工具住在同一个 `main.js` 里，声明风格也一致——往 `$phooks` 里 push：

```js
var $phooks = [];

$phooks.push({
  name: 'onBeforeSend',
  handler: function (payload) {
    // payload.text 是本条消息
    if (payload.text.startsWith('#note ')) {
      return { text: '[笔记] ' + payload.text.slice(6) };
    }
    return '';   // 空串 = 不干预
  }
});
```

一个插件可以同时声明多个钩子、多个工具。**只写钩子、不写工具也是合法插件**
（宿主不再要求必须声明工具）。

### 13.3 五个钩子

| 钩子 | 何时触发 | 入参 | 返回 |
|---|---|---|---|
| `onAppStart` | 所有插件加载完成后 | `{ pluginId }` | 忽略 |
| `onBeforeSend` | 用户消息发出前（斜杠命令 / `!shell` 判断之前） | `{ text }` | `{ text }` 或纯字符串 |
| `onPromptInject` | 每次构建 AI 系统提示词时（十一期） | `{ base, conversationId }` | 要追加的文本 |
| `onAfterReply` | AI 回复完成、文本已落地 | `{ text, conversationId }` | 忽略 |
| `onBeforeTool` | 每次工具执行前 | `{ tool, args }` | `{ block: '原因' }` 则拦下 |
| `onAfterTool` | 工具执行完、结果回给模型前 | `{ tool, args, result }` | `{ result }` 或纯字符串 |

几个关键行为：

**`onBeforeSend` 是链式的**。多个插件都注册时按顺序依次处理，后一个拿到的是前一个的
输出。返回空串表示放行，返回 `{text: ''}` 才是真的清空（这两种情况必须区分开）。

**`onPromptInject` 是累加的**。与 `onBeforeSend` 相反，多个插件都注册时全部拼接（谁也
不覆盖谁）——提示词是累加性质的，一个插件覆盖另一个会丢信息。它的 `base` 只给前
2000 字（插件通常只想知道个开头），返回值追加在系统提示词末尾。

> 这是能力最强的钩子：插件能影响 AI 的全部行为。它同样受 `hook` 危险权限管着，
> 并且有 10 秒超时（超时则该插件本次被跳过，不影响对话继续）。

**合成轮不进钩子**。后台通知、上下文压缩这类系统内部生成的消息（走 `overrideText`
通道）不会触发 `onBeforeSend`——让插件掺和进去只会污染内部流程。

**`onBeforeTool` 的 `block` 优先于执行**。多个插件里第一个返回非空 `block` 的生效，
工具不会真的跑，那段文字会作为工具结果交给模型。这是**唯一能改变流程控制**的钩子。

**`onAfterTool` 也会作用在插件自己的工具上**。总输出超过 4000 字符时截断，
是它最有价值的用法之一：读大文件时能省下大量上下文。

### 13.4 完整例子

```js
var $log = { sends: [], blocked: [], tools: [] };

var $phooks = [];

// 1. 消息前缀改写
$phooks.push({
  name: 'onBeforeSend',
  handler: function (p) {
    $log.sends.push(p.text.slice(0, 40));
    var m = /^#rewrite\s+([\s\S]+)$/.exec(p.text);
    return m ? { text: '请用一句话回答：' + m[1] } : '';
  }
});

// 2. 拦下危险命令
$phooks.push({
  name: 'onBeforeTool',
  handler: function (p) {
    if (p.tool !== 'terminal') return '';
    var cmd = String(p.args && p.args.command || '');
    if (/rm\s+-[a-zA-Z]*r[a-zA-Z]*f[a-zA-Z]*\s+\/(\s|$)/.test(cmd)) {
      $log.blocked.push(cmd.slice(0, 40));
      return { block: '该命令会删除根目录，已拦下' };
    }
    return '';
  }
});

// 3. 超长结果截断
$phooks.push({
  name: 'onAfterTool',
  handler: function (p) {
    var r = String(p.result || '');
    $log.tools.push(p.tool + ' → ' + r.length);
    return r.length > 4000
      ? { result: r.slice(0, 4000) + '\n…（已截断，原长 ' + r.length + '）' }
      : '';
  }
});
```

内存里的 `$log` 可以直接通过同插件的工具暴露给 AI 看（同一个 eval 作用域，闭包共享）：

```js
var $ptools = [{
  name: 'hook_demo_status',
  description: '查看钩子插件的运行记录',
  parameters: { type: 'object', properties: {} },
  handler: function () { return { ok: true, log: $log }; }
}];
```

### 13.5 三条硬约束（违反会拖垮整轮对话）

**1. 必须快。** 钩子在主链路上同步执行。一次消息发送会串行跑完所有插件的
`onBeforeSend`，一次工具调用会跑 `onBeforeTool` + `onAfterTool`。单次超过 200ms
宿主会写一条警告日志——看到它就该改代码了。

**2. 不要写死循环、不要发网络请求。** 宿主给钩子设了 **10 秒超时**：超时后会中断
QuickJS 执行、忽略这个钩子的返回值，对话照常继续。但没有超时的**副作用**会留下来——
比如已经写了一半的文件。偶尔的慢请求会被截断而不是保护你。

超时还有一层代价：中断标记在当前 QuickJS 实例上无法单独清除，所以宿主会在下一次
执行前**换一个新的 VM 并把插件脚本重新装载**。对插件而言这意味着 **`main.js` 顶层的
变量会被重置**——计数、缓存、累加器全部归零。别靠模块级变量维持跨消息状态，
要存就落磁盘。

**3. `main.js` 里没有 `ctx`。** 宿主桥只注入给界面脚本（`ui/*.js`），钩子里拿不到
`ctx.http` / `ctx.file` 等能力，只能做纯 JS 计算。需要宿主能力的活应该做成**工具**
让 AI 调，而不是塞进钩子。

### 13.6 排错

钩子写错时**不会**让 App 崩溃——宿主捕获所有异常并记日志，那一轮对话照常进行，
只是该钩子表现为"没生效"。排查顺序：

1. `plugin.json` 里有没有声明 `"hook"` 权限（没声明时钩子被静默忽略，日志里有记录）
2. 发送日志里搜 `PluginHook`，看注册成功与否（`插件 xx 注册钩子：...`）
3. 确认 `$phooks.push` 的对象同时有 `name`（字符串）和 `handler`（函数）——
   缺一个就被跳过
4. 钩子名拼写。只有 `onAppStart` / `onBeforeSend` / `onAfterReply` /
   `onBeforeTool` / `onAfterTool` 五个，其它名字会被忽略（这是为了向前兼容）

## 14. 布局与富文本（八期）

### 14.1 `weight` / `grow`：把剩余空间分给某个子元素

以前插件做不出「左边文字、右边按钮」这种效果：`fillMaxWidth` 会把后面的兄弟挤出屏幕。
现在给 `column` / `row` 的**直接子节点**加权重即可：

```js
ctx.UI.Row({}, [
  // 占满剩余宽度的文字，长文本会自动折行而不是把按钮顶出去
  ctx.UI.Text({ text: longText, weight: 1, fillMaxWidth: true }),
  ctx.UI.Button({ text: '重试', onClick: 'retry' })
])
```

- `weight: 2` 与 `weight: 1` 按 2:1 分配剩余空间
- `grow: true` 是 `weight: 1` 的简写
- 权重**只在 `column` / `row` 的直接子节点上生效**：`box`、`lazycolumn`、
  `grid` 里的子节点没有这个概念（Compose 的作用域就没给）
- `row` 开启 `wrap: true`（自动换行）时，权重也不生效——换行布局算不出"剩余空间"

`weight` 与 `fillMaxWidth` 的区别：后者要求父容器**全部**宽度，前者只吃**剩余**宽度。

### 14.2 网格：`grid` / `lazyverticalgrid`

```js
ctx.UI.LazyVerticalGrid({
  columns: 3,          // 固定列数；或 "auto" 按 minCellWidth 自适应
  minCellWidth: 100,   // columns:"auto" 时每格最小宽度
  spacing: 8,          // 横纵间距
  height: 300
}, cards)
```

别名：`grid` / `gridview` / `lazygrid` / `lazy_vertical_grid` 都指向同一个组件。
`columns` 默认 2。

### 14.3 Markdown：`markdown`

直接渲染 Markdown，用的是聊天页同一套解析与渲染器，所以**语法和视觉效果都跟 AI 回复完全一致**：

```js
ctx.UI.Markdown({
  text: '## 标题\n\n- 列表项\n- 另一项\n\n```js\nconsole.log(1)\n```',
  fontSize: 14,
  color: 'text'
})
```

支持：标题、段落、有序/无序列表、代码块（带复制）、引用、表格、分割线、图片、行内 `code`/**粗体**/链接。

> 注意：`markdown` 渲染出来的内容是**只读**的，里面的链接点击由宿主接管。
> 需要在 markdown 里嵌入可交互按钮是做不到的——那是 `markdown` 与纯组件混排的边界。

### 14.4 插件内多页路由：`ctx.router`

以前插件只能做单页。现在可以做「列表 → 详情」这种两级结构，**返回键自动生效**。

```js
function Screen(ctx) {
  const route = ctx.router.current();

  if (route.name === 'detail') {
    return ctx.UI.Column({ padding: 14 }, [
      ctx.UI.Text({ text: '详情：' + route.params.title }),
      ctx.UI.Button({ text: '返回', onClick: 'goBack' })
    ]);
  }

  // 首页
  return ctx.UI.Column({ padding: 14 }, [
    ctx.UI.Button({
      text: '打开详情',
      onClick: { name: 'openDetail', params: { title: '第一条' } }
    })
  ]);
}
```

配套的 action 里：

```js
case 'openDetail':
  ctx.router.push('detail', { title: action.params.title });
  break;
case 'goBack':
  ctx.router.pop();
  break;
```

API：

| 方法 | 说明 |
|---|---|
| `ctx.router.current()` | 当前页 `{ name, params }`，初始是 `{ name: 'root' }` |
| `ctx.router.push(name, params)` | 入栈并重渲染 |
| `ctx.router.pop()` | 出栈；栈已空时返回 `false` 且不做事 |
| `ctx.router.replace(name, params)` | 替换当前页（不增加栈深） |
| `ctx.router.reset()` | 回到只有 `root` 的初始状态 |
| `ctx.router.canGoBack()` | 栈深 > 1 |
| `ctx.router.stack()` | 整个栈的副本 |

**返回键行为**：用户按系统返回时，如果栈里还有页就先回退一页，栈空了才关闭插件面板。
插件**不需要**自己处理返回键，也不用担心"按返回直接把面板关了"。

没用 `ctx.router` 的插件行为完全不变（返回键直接关面板）。

## 15. 插件悬浮窗（十期）

让插件的界面脱离 App，浮在其它应用之上。**不需要写第二份界面**——悬浮窗直接渲染
你自己的 `ui/panel.ui.js`，面板和浮窗是同一份代码。

### 15.1 声明权限

```json
{ "permissions": ["overlay"] }
```

`overlay` 是**危险权限**。另外宿主本身还需要系统级的「显示在其他应用上层」授权，
没开的话 API 会返回明确提示而不是静默失败。

### 15.2 API

```js
// 先问一下能不能浮（宿主有没有系统悬浮窗授权）
const c = ctx.overlay.canShow();     // → { ok, canShow }

// 显示 / 隐藏
await ctx.overlay.show();                       // → { ok, accepted:true }
await ctx.overlay.show({ width: 0.5 });         // 屏宽 50%
await ctx.overlay.show({ width: 320 });         // 320dp 固定宽
await ctx.overlay.show({ maxHeight: 0.35 });    // 最高不超过屏高 35%
await ctx.overlay.show({ focusable: true });    // 需要窗内输入框时
await ctx.overlay.hide();                       // → { ok }
ctx.overlay.isShowing();                        // → { ok, showing }
```

`show()` 的选项：

| 字段 | 默认 | 说明 |
|---|---|---|
| `width` | `0.82` | 窗宽。`0<n≤1` 当屏宽比例，`>1` 当 dp |
| `height` | `0` | 固定窗高，用法同 `width`。省略（`0`）则按内容自适应 |
| `maxHeight` | `0.60` | 最大高。同上，`0.8` = 屏高 80%。`height` 会受它约束 |
| `minWidth` | `160` | 拖拽缩放的最小宽度（dp） |
| `minHeight` | `80` | 拖拽缩放的最小高度（dp） |
| `focusable` | `false` | 是否抢输入焦点（默认不抢，见 15.4） |
| `chrome` | `true` | 是否画宿主外壳（标题栏 + 关闭按钮 + 缩放手柄）。`false` = 窗口就是你自己的界面，见 15.8 |
| `transparent` | `false` | 背景透明（不铺面板底色与圆角）。**`chrome:false` 时默认就是透明** |
| `dragAnywhere` | `false` | 整个窗口可拖（而不只是标题栏）。`chrome:false` 时默认生效 |
| `rememberPosition` | `true` | 记住位置与大小，下次 `show()` 还原（按插件存） |

所有字段都可省略，省略就用默认值；类型写错也不会报错，直接用默认值。

> `height` 与 `chrome:false` 是一对：窗口高度按内容自适应时，气泡多一行、少一行
> 窗口就跟着变高变矮，整个宠物会上下跳。固定尺寸的浮窗记得把 `height` 写上。

完整例子：

```js
ctx.UI.Button({
  text: '浮到其它应用上',
  onClick: function () {
    ctx.overlay.show().then(function (r) {
      if (!r.ok) ctx.showToast('没能显示：' + r.error);
    });
  }
})
```

### 15.4 尺寸与缩放

**打开时指定**：给 `show()` 传 `width` / `maxHeight`，见上面的表。

`show()` 返回 `{ok:true, accepted:true}` 只代表**请求已被接受**，不代表窗口已经出来。
实际流程分两步：

1. 立即：在主线程创建窗口骨架（此时窗内显示“界面为空”）
2. 随后：在后台加载插件脚本并渲染内容

所以调完 `show()` 立刻查 `isShowing()` 可能还是 `false`，稍等一下（一般几百毫秒）才行。

为什么必须异步：窗口创建必须在**主线程**（Compose 和 WindowManager 的硬性要求），
而插件脚本加载是纯 CPU 的 QuickJS 初始化、不能占主线程；更关键的是，`show()` 是从
插件动作派发里调进来的，那一刻面板自己的 QuickJS 引擎正在跑，在同一个线程里建
第二个引擎会直接死锁（实测会卡死且面板失去响应）。

**打开后手动缩放**：拖窗口**右下角的把手**即可。宽度范围是 `minWidth` ~ 屏宽，
高度是 `minHeight` ~ 屏高 92%。

拖顶部那条则是移动位置（不是改大小）。

**窗口缩小时内容等比缩放**：以首次显示时的窗口尺寸为基准，窗口缩到多少，
界面（字号、间距、控件）就跟着缩到多少 —— 不需要在 JS 里自己算缩放。
取宽、高两个比例的较小者，保证两个方向都装得下；窗口比基准大时不放大，
多出来的空间给内容重排。缩到 0.4 倍（下限，再小就没法看了）后不再继续缩，
剩余空间不足交给滚动。宿主自己的标题栏不参与缩放，仍是原尺寸。

> **位置与大小默认会记住**：拖到哪、缩到多大，下次 `show()` 还原（跨重启也在）。
> 不想要这个行为就传 `rememberPosition: false`。

### 15.5 焦点：默认不抢键盘

默认 `FLAG_NOT_FOCUSABLE`，也就是**不抢输入焦点**。这是刻意的：悬浮窗一出现就抢焦点，
会把用户当前应用的软键盘顶掉——正在别的 App 里打字时突然弹一个键盘，体验非常糟糕。

代价：默认状态下浮窗里的 `TextField` 收不到键盘输入。

需要输入的插件传 `focusable: true`，此时会抢焦点。只在"浮窗本身就是主要输入界面"时用。

### 15.6 行为与限制

- **可拖动**：按住顶部那条（写着「插件浮窗」的位置）左右上下拖；`chrome:false` 时
  拖窗口任意位置
- **可缩放**：拖右下角小方块（见 15.4）。缩小时界面等比跟着缩（下限 0.4 倍），
  不是单纯把内容裁掉。**无外壳（`chrome:false`）时没有把手，不能手动缩放**，
  尺寸由 `width` / `height` 定
- **关闭**：右上角「关闭」按钮，或插件自己调 `ctx.overlay.hide()`
- **高度上限**：默认屏高 60%（可由 `maxHeight` 改），**内容超出时自动滚动**（宿主按树类型分流：含 WebView/PullToRefreshBox/无 height 的 Lazy* 时由组件自身滚动；含有固定 height 的 Lazy* + 普通布局时由宿主外层滚动）。无外壳时不自带滚动外的额外包装
- **位置与大小默认持久**：同一插件下次 `show()` 回到原地原尺寸；`rememberPosition:false` 可关
- **一个插件一个浮窗**：重复 `show()` 不会叠加新窗口，只会复用已存在的那个；
  面板轨道和后台脚本轨道共用的也是同一个窗口
- **状态会被保留**：浮窗关闭时才释放 QuickJS 会话，所以浮窗里点的按钮、填的状态在
  隐藏→再显示之间**会丢**（等价于重新打开面板）。需要跨开关保留的东西请写进
  `ctx.setEnv` 或 `ctx.store`

### 15.7 什么时候该用悬浮窗

适合：常驻的小工具面板（计时器、网速、剪贴板历史、音乐控制、记账快捷入口）。

不适合：
- 需要复杂输入的界面（焦点问题）
- 一次性的大界面（直接开面板更合适，浮窗空间有限）
- 需要常驻后台刷新的（浮窗只是界面，没有独立的后台执行；刷新要靠插件自己的事件驱动）

### 15.8 无外壳浮窗（桌面宠物形态）

想要「窗口本身就是插件内容」而不是「一个带标题栏的小面板」时：

```js
ctx.overlay.show({
  width: 164,           // 固定尺寸：形象多大，窗口就多大
  height: 232,
  chrome: false,        // 不画宿主标题栏 / 关闭按钮 / 缩放手柄
  transparent: true,    // 不铺底色，由你的界面决定画什么
  dragAnywhere: true,   // 整个窗口可拖
  rememberPosition: true
});
```

四个关键后果，写之前想清楚：

- **没有关闭按钮了**：用户唯一能靠的是你的界面，你得自己给收回入口（按钮、长按、
  点两下……都行）。`ctx.overlay.hide()` 就是收回
- **没有缩放手柄了**：显示时窗口尺寸由 `width`/`height` 决定；已显示时改配置应调用
  `ctx.overlay.resize(widthDp, heightDp)` 同步调整窗口，再重渲染内容。重复 `show()` 不会修改已显示窗口的尺寸
- **透明底是真透明**：画布/贴图自带的透明区域会真的透出桌面，不再是配上底色的一块卡片。
  无外壳（`chrome:false`）时即使不写 `transparent: true` 也是透明的，View 背景也会被显式清掉
- **图片占位不会出现**：无外壳窗口里加载中的图不画任何东西（透明），加载失败也不显示灰框与
  错误文案 —— 宠物身上冒出一块灰色圆角方块会导致“多了一块底”。面板里仍保留占位，便于排查
- **触摸区域是整个窗口矩形，不是可见像素**：窗口不要做得比形象大太多，否则周围的
  透明区域会挡住底下 App 的点击（这是系统悬浮窗的硬限制，插件侧无解）

#### 让它会走、会贴边、能穿透（`moveTo` / `geometry` / `setPassThrough`）

想让浮窗本体在屏幕上移动（蹓跶、贴边、到边上缩进去）不需要重渲染 ——
**只改窗口坐标**：

```js
// 20fps：读当前几何 -> 朝目标挪一步。全程不碰 state，不重渲染。
setInterval(function () {
  var g = ctx.overlay.geometry();   // { x, y, width, height, screenWidth, screenHeight, density, dragging, passThrough }
  if (!g.ok || !g.showing) return;
  if (g.dragging) return;           // 用户正在拖：先让位
  var maxX = Math.max(0, g.screenWidth - g.width);
  var next = Math.min(maxX, Math.max(0, g.x + 6));
  ctx.overlay.moveTo(next, g.y);
}, 50);
```

| API | 说明 |
|---|---|
| `ctx.overlay.geometry()` | 同步返回位置与屏幕尺寸（对象） |
| `ctx.overlay.moveTo(x, y)` | 把窗口挪到屏幕坐标（px）。**允许负值/超出屏幕**，贴边收进去就靠它（宿主限制：最多 80% 移出屏幕，至少留 20% 可见） |
| `ctx.overlay.resize(widthDp, heightDp)` | 调整已显示窗口的宽高（dp，返回 `{ok:true}`），保留坐标，不重建窗口、不缩放内容；更改图片尺寸时也要调整窗口。尺寸限定在屏幕范围内 |
| `ctx.overlay.setPassThrough(on)` | 切换触摸穿透：开着时窗口完全不吃触摸 |
| `ctx.overlay.say(text, ms)` | 在浮窗头顶冒一句话（**独立窗口、不接收触摸**），默认 4200ms |

几条经验（都是踩过的）：

- **一定要看 `dragging`**：你自己在每帧改坐标，用户同时拖就是抢方向盘（拖不动/发抖）。
  插件停手，让手指先走完
- **`moveTo` 是异步生效的**，不能当“已经到达”用；下一次 `geometry()` 才是真值
- **负坐标真的能移出屏幕**（宿主给浮窗加了 `FLAG_LAYOUT_NO_LIMITS`），但最多 80%：
  宿主会把坐标夹到「至少留 20% 可见」，免得插件把窗口移到屏外找不回来
- **穿透开了插件就点不到自己了**（连关都关不掉）。所以开关入口要留在插件面板里
  （面板是另一个容器，`ctx.container === 'panel'`，不受穿透影响）
- 走动时**不要**用 `setState` 逐帧改坐标（那会重建整棵 UI 树），而是 `moveTo`；
  呼吸/浮动这类循环动作交给节点的 `animate`，两边叠起来才像活的
- 窗口仍然是**矩形**：透明区域也会拦触摸。只能靠“贴边/缩进去/调小尺寸”减少遮挡，
  系统没有“按透明像素穿透”的公开能力
- **浮窗里想显示文字（说话、提示）用 `ctx.overlay.say()`，不要用 `Text` 组件**：
  浮窗尺寸往往紧贴内容（比如只有 `size+8dp`），摆不下字；把浮窗改大会多挡一圈触摸。
  `say()` 单独开一个 `FLAG_NOT_TOUCHABLE` 的窗口，能画得比浮窗宽且完全不挡操作，
  自动定位在浮窗上方居中（贴边/超出屏幕会夹回屏内），到时自动消失。
  **它会跟着浮窗走**：`moveTo` 或用户拖窗口时气泡会同步重定位，不会留在原地

```js
ctx.overlay.say('喵～', 4200);   // 头顶冒一句，4.2 秒后自己消失
```

#### 下次打开 App 时自动恢复（`overlayAutoStart`）

浮窗活在**宿主进程**里，App 一退出（进程被杀）就没了。想要「每次打开 App 它还都在」，
在清单里声明：

```json
{ "overlayAutoStart": true }
```

宿主的实际行为（三个条件同时满足才恢复）：

1. **自启开关是开的**——用户在「插件管理 → 插件配置」里能自己关掉，
   用户设置优先于清单默认值
2. **上次退出时浮窗还开着**——用户点过「收回」就不会再自动弹
3. **系统悬浮窗权限还在**——没有就安静跳过，不在启动时弹系统设置页

尺寸/样式沿用上次 `show()` 的选项（宿主存了副本），所以恢复出来的宠物和关 App 前一样大、
同一个位置。插件改了配置则在它自己下次 `show()` 时生效。

> 「收回」与「自动恢复」是成对的：收回 = 明确表态不要它了，下次不会自动出现；
> 想让它回来就再点一次「放到桌面」。

#### 后台保活（服务轨道）

面板关掉后浮窗还在，但**宿主进程被杀，浮窗会一起没**。要「一直在」就得靠定时任务／
后台脚本把它拉回来（清单里声明 `schedule` + `permissions` 含 `schedule`）：

```js
// service/pet.js
exports.onSchedule = function (taskId) {
  if (taskId !== 'keep-alive') return;
  // 服务轨道的 overlay API 返回 JSON 字符串（没有 Promise 封装），要先 parse
  var st = JSON.parse(ctx.overlay.isShowing() || '{}');
  if (st.showing) return;
  var can = JSON.parse(ctx.overlay.canShow() || '{}');
  if (!can.canShow) return;          // 没系统悬浮窗权限就安静跳过
  ctx.overlay.show({ width: 164, height: 232, chrome: false, transparent: true, dragAnywhere: true });
};
```

两条轨道调 `ctx.overlay.*` 的返回形式不同：

| 调用 | UI 轨道（`ui/*.js`） | 服务轨道（`service/*.js`） |
|---|---|---|
| `ctx.overlay.show(opts)` | Promise（`await` 或 `.then`） | 同步返回 JSON 字符串 |
| `ctx.overlay.hide()` | Promise | 同步返回 JSON 字符串 |
| `ctx.overlay.isShowing()` | 对象 `{ ok, showing }` | JSON 字符串，需 `JSON.parse` |
| `ctx.overlay.canShow()` | 对象 `{ ok, canShow }` | JSON 字符串 |

两条轨道拿到的是**同一个窗口**：面板已经开了浮窗，后台任务查 `isShowing()` 会看到
`true`，不会又拉一个出来。同样地，`show()` 是异步生效的（见 15.4），调完立即查
`isShowing()` 可能还是旧值。

## 16. 插件自带配色（主题）

插件可以在 `plugin.json` 里声明一套配色，让自己在任何宿主主题下都保持品牌观感。

### 16.1 声明

```json
{
  "id": "my.plugin",
  "theme": {
    "primary": "#7C4DFF",
    "surface": "#1C1B22",
    "text": "#E8E6F0",
    "textSecondary": "#9E9BA8",
    "border": "#3A3742",
    "error": "#FF5252"
  }
}
```

可用的 key 与宿主内置 token 同名：`primary` / `surface`（或 `background`）/
`text` / `textSecondary` / `border` / `error` / `success` / `warning`。
值写 `#RGB`、`#RRGGBB` 或 `#AARRGGBB`。

### 16.2 怎么生效

**只在组件显式用了 token 时才替换**：

```js
ctx.UI.Text({ text: '标题', color: 'primary' })      // → #7C4DFF（取你在 theme 里的定义）
ctx.UI.Surface({ background: 'surface' }, [...])     // → #1C1B22
ctx.UI.Text({ text: '普通正文' })                     // → 仍用宿主默认色
```

也就是说：**你写 token，主题才有意义；写 `#hex` 就按你给的来；什么都不写，跟宿主走。**

为什么不做成"没写 color 也自动跟随"：同一个属性名在不同组件里语义不同——
`Text` 的 `color` 是正文色，`Button` 的 `color` 却是强调色（默认取 `primary`）。
自动兜底会让按钮文字变成正文色，深色底浅色字就可能反过来看不清。**宁可少自动，
也不要视觉错乱。**

所以想要整套配色统一，就在组件上明确写 token，这是插件作者本来就该做的事。

### 16.3 范围与限制

- 只影响**插件自己的界面**（面板和悬浮窗都算），碰不到宿主 UI
- 同一插件的面板与悬浮窗共用一套配色；不同插件之间互不干扰
  （主题存在节点树上，不是进程级全局值——两者可能同时在主线程重组，全局值会串）
- 插件没声明的 key 会回退到宿主内置 token，所以只覆盖 `primary` 也是合法的
- 深浅色：宿主切换深色/浅色时，未覆盖的 token 会自动跟随；覆盖过的按你给的值

### 16.4 建议

- **只覆盖品牌色**（`primary`）最安全，宿主负责其余部分，深浅色都好看
- 想覆盖 `text` / `surface` 就把一整套都覆盖掉，不要只改一半——
  只改 `surface` 不改 `text` 容易出现"深底深字"
- 别在 `theme` 里放非颜色值，解析不出来会静默回退到宿主默认色

## 17. 记忆与聊天记录

插件可以读 AI 的记忆库、读聊天记录——这是"插件参与 AI 流程"的基础。
两个能力都是危险权限，因为里面是用户的隐私内容。

### 17.1 记忆库（`ctx.memory`）

```json
{ "permissions": ["memory"] }
```

| 方法 | 说明 |
|---|---|
| `ctx.memory.list(keyword, scope, limit)` | 列出/搜索记忆，返回摘要（`value` 只给前 200 字） |
| `ctx.memory.read(key, scope)` | 读某条记忆全文 |
| `ctx.memory.save(key, value, category, scope)` | 写入记忆（`type` 固定为 `ai`） |
| `ctx.memory.remove(key, scope)` | 删除该 key 的记忆 |

`scope` 取 `'global'`（长期记忆，默认）或 `'project'`（当前项目记忆）。
`keyword` 为空表示不过滤，大小写不敏感地匹配 key 与正文。

```js
// 搜一搜关于“部署”的记忆
const r = ctx.memory.list('部署', 'global', 10);
// → { ok, scope, count, items: [{ key, type, category, length, preview }] }

// 看全文
const one = ctx.memory.read('构建测试流程偏好', 'global');
// → { ok, key, type, category, value }

// 存一条
ctx.memory.save('我的编辑器偏好', '偏好使用 4 空格缩进', 'preference', 'global');

// 删
ctx.memory.remove('过时的记忆');
```

`list` 只返回摘要，是为了避免把大体量文档（如内置规则文档 13KB、插件指南 24KB）
一次性推给插件。需要全文就 `read` 那一条。

### 17.2 聊天记录（`ctx.chat`）—— 只读

```json
{ "permissions": ["chat"] }
```

| 方法 | 说明 |
|---|---|
| `ctx.chat.list(limit)` | 会话列表（按最近活跃倒序） |
| `ctx.chat.current()` | 当前打开的会话 |
| `ctx.chat.messages(limit)` | 当前会话最近 N 条消息（按时间正序） |

```js
const cur = ctx.chat.current();
// → { ok, conversationId, title, requestCount }

const msgs = ctx.chat.messages(20);
// → { ok, conversationId, count, messages: [{ role, time, length, content }] }
```

**为什么只有只读**：让插件"替用户发消息"需要串起整条 AI 请求链（模型选择、工具循环、
流式渲染、中断控制），出错就是半截消息留在会话里、或者两个流程同时跑。插件想影响
对话应该用**钩子**（第 13 章），那才是为这个设计的。

**消息条数与长度都有上限**：单次最多取 100 条，单条正文截断到 2000 字。
这不是随意设的——整会话全量读取在长对话上会直接把内存吃满（真实 OOM 过）。
插件要处理长文本请分多次取，不要指望一次拿全。

### 17.3 发起 AI 任务（`ctx.chat.runTask`）

```json
{ "permissions": ["chat_task"] }
```

让插件**主动开一轮 AI 对话**，让 AI 按指令干活。定时任务插件就靠它。

```js
await ctx.chat.runTask('总结今天的科技新闻', { newConversation: true });
// → { ok: true, conversationId: 31, started: true }
```

| 参数 | 说明 |
|---|---|
| `prompt` | 交给 AI 的指令 |
| `newConversation` | 默认 `true`：新建一个**后台会话**（不抢当前对话）；`false` 则发到当前会话 |

**三个必须知道的语义**：

1. **只发起、不等结果**。AI 回复要几十秒，插件回调里同步等会卡死 QuickJS。
   返回值里的 `conversationId` 是去看结果的地址，不是结果本身。
2. **`newConversation: true` 不切前台**。它只往库里插一条 `active=false` 的会话，
   再用 `sendMessage(targetConversationId)` 唤醒它。这样定时任务在后台跑时不会把你
   正在看的对话顶掉。
3. **`started: false` 不是错误**，表示这次没起成（未选模型、并发已满、当前有请求在跑）。
   要做重试就检查这个字段，别把 `ok: false` 当成权限问题。

**会消耗 Token**。这是它单独占一个权限（`chat_task`）而不是并进 `chat` 的原因：
读会话列表风险低，而发起任务会真的花你的钱、跑工具、改工作区。

### 17.4 组合用法：让 AI 知道插件看到了什么

钩子 + 记忆是最自然的组合。比如插件在后台采集了数据，想让 AI 在回答时用上：

```js
// main.js
$phooks.push({
  name: 'onPromptInject',
  handler: function (p) {
    // 注意：main.js 里没有 ctx，这里只能读自己维护的内存变量，
    // 或者事先通过工具让 AI 把数据写进记忆。
    return '当前设备 CPU 温度为 41°C，若用户问到性能可以直接引用。';
  }
});
```

`main.js` 拿不到 `ctx`（宿主桥只注入给界面脚本），所以想读实时数据得靠插件自己的
工具接口中转：界面脚本用 `ctx.callTool` 拿数据，写进记忆，钩子再从记忆里读。

## 18. Operit 插件兼容层

OpenX 能直接安装 **Operit** 的 ToolPkg 插件（`.toolpkg` 包，或含 `manifest.json` 的目录），
不需要对方改一行代码。导入时宿主自动识别、转换、装载。

### 18.1 识别与安装

导入压缩包或目录时，若某个子目录里有 `manifest.json` 且含 `toolpkg_id` 字段，
就按 Operit 兼容包处理：生成一份带 `"compat": "operit"` 标记的 `plugin.json`，
原样铺开它的目录结构。

入口脚本**装载时现场生成**、不落盘（`OperitCompat.buildEntrySource`）。好处是兼容层
改进后已安装的插件立刻受益，**不必让用户重新导入**。

工具清单来自**子包 JS 文件头的 `METADATA` 注释块**，不是 manifest：

```js
/* METADATA
{

  "display_name": { "zh": "OpenCode 配置", "en": "OpenCode Config" },

  ]
}
*/
```

### 18.2 支持的 API

| 全局 | 提供的方法 |
|---|---|
| `Tools.Files` | `read` `write` `exists` `mkdir` `list` `remove` `stat` `deleteFile` `move` `copy` `info` `unzip` `download` |
| `Tools.Net` | `httpGet` `httpPost` `http`（通用请求：`{url, method, headers, body}`） |
| `Tools.System` | `sleep` `toast` `terminal.create/exec/execStreaming/close` |
| `ToolPkg` | `getConfigDir` `readResource` + 全部 `register*`（见下） |
| `Env` | `get` `set`（进程内存，**不跨重启持久**） |
| `UI` | 由 `ctx.UI` 提供，组件与第 5 章完全一致 |
| `ctx.MaterialTheme` | 已映射，`colorScheme` 可用 |

所有 `register*` 方法都有**空桩**（返回 undefined、不报错）：`registerUiRoute`、`registerNavigationEntry`、`registerToolboxUiModule`、`registerDesktopWidget`、`registerTool`、`registerAppLifecycleHook`、`registerSystemPromptComposeHook`、`registerToolPromptComposeHook`、`registerPromptFinalizeHook`、`registerPromptEstimateFinalizeHook`、`registerPromptInputHook`、`registerPromptHistoryHook`、`registerPromptEstimateHistoryHook`、`registerSummaryGenerateHook`、`registerChatViewHook`、`registerChatInputHook`、`registerChatMessageHook`、`registerChatRuntimeHook`、`registerChatMessageMenuItem`、`registerMessageProcessingPlugin`、`registerXmlRenderPlugin`、`registerInputMenuTogglePlugin`、`registerToolLifecycleHook`、`registerAiProvider`。其中只有 `registerNavigationEntry` 真正被消费（见 18.6）。`ToolPkg.ipc.on/off` 也是空桩，`ipc.call` 返回 reject。

界面入口按约定递归找 `.ui.js`（tsc 产物常在 `dist/ui/<route>/index.ui.js`），
取路径最短的那个；产出以 `exports.default = Screen` 结尾即命中 OpenX 的入口解析。

### 18.3 不生效的 API（装了但没反应）

这些调用**不报错、也不产生效果**，是排查"插件部分功能失灵"的第一嫌疑：

- `ToolPkg.registerAppLifecycleHook` / `registerSystemPromptComposeHook` /
  `registerPromptFinalizeHook` / `registerChatViewHook` / `registerAiProvider` 等全部钩子类注册（见 18.2 空桩清单）
- `ToolPkg.ipc.call`（返回 reject）/ `ToolPkg.wasm.call`（不支持 WASM 模块）
- `workflow_templates` / `workspace_templates`：OpenX 无对应概念，整块忽略
- `Tools.Chat.*` / `Tools.SoftwareSettings.*`：OpenX 无对应概念

`Env` 与 `Tools.System.terminal` 都做了简化：前者只在进程内存活；后者每次 `exec`
独立跑完返回，**不保留 `cd`、环境变量的跨命令状态**。

### 18.4 兼容性诊断报告

导入时宿主会生成 `compat_report.txt`（落在插件目录），并在**插件管理页 → 点开该插件**
的详情里以「兼容性诊断」区块显示：⚠ 橙色是**会丢功能**，· 灰色是仅提示。

报告内容：

- `enabled_by_default=false` → 导入时按禁用入库
- 子包默认禁用清单（OpenX 无子包级开关，会按启用处理并提示）
- `resources` 声明的路径在包内不存在 / 指向目录（兼容层只按单文件取）
- `workflow_templates`、`workspace_templates` 的数量
- 源码里调用了上述空实现 API 的**次数**（扫 `.js` 得出）
- METADATA 声明了但模块没导出的工具（装载时自动筛除，避免给 AI 一个必失败的工具）
- METADATA 里兼容层不识别的键
- 子包清单：显示名（按宿主语言选 `zh`/`en`）、工具数、默认启用态

老版本导入的包没有报告文件，**首次打开管理页详情时会自动补生成**。

### 18.5 `enabled_by_default` 的实际语义

两处都能写，含义不同：

| 位置 | 键名 | 缺失默认 | OpenX 行为 |
|---|---|---|---|
| manifest 根 | `enabled_by_default` | `true` | 决定导入时的默认启停 |
| `subpackages[]` | `enabled_by_default` | — | **不被读取**（见下） |
| 子包 METADATA | `enabled_by_default` / `enabledByDefault` | `false` | 进诊断报告 |

⚠️ **Operit 官方源码的 `ToolPkgManifestSubpackage` 只解析 `id` 与 `entry`**，
`subpackages[]` 里写的 `display_name` / `description` / `enabled_by_default`
会被 `ignoreUnknownKeys` **静默丢弃**。子包的显示名与默认启用态的**权威来源是
子包 JS 文件头的 METADATA**。官方文档 `TOOLPKG_FORMAT_GUIDE.md` 与实现不一致，
遇到冲突以解析代码为准。

OpenX 没有子包级开关 UI，所以子包的 `false` 不会真的禁用它，只在报告里提示。

两种键名（蛇形 `enabled_by_default`、驼峰 `enabledByDefault`）都接受，值也接受
`"true"/"1"/"yes"/"on"` 这类字符串——与官方宽松转换一致。

### 18.6 侧边栏快捷入口

插件 `main.ts` 里 `ToolPkg.registerNavigationEntry({ surface: "main_sidebar_plugins", ... })`
声明的入口，OpenX 会**在装载时执行 main.js 收集**，映射成侧边栏快捷项：

- 只取 `surface` 含 `main_sidebar` 的定义（其他 surface 如设置页、聊天菜单，OpenX 没有对应位置）
- `title` 支持多语言对象，按宿主语言选 `zh`/`en`
- `icon` 取末段映射（如 `Icons.Code` → `code`）
- 点击行为固定为 `openUi`（打开插件面板）

> 这里说的是**自动收集**的导航入口，行为写死成 `openUi`。若想在侧边栏出现「用浏览器打开」
> 这类入口，要在 `plugin.json` 里手写 `quickActions` 并指定 `action: "openUrl"`（见 [第 2 节](#2-目录结构与-pluginjson)）。

收集在每次插件重载时重建（不落盘），所以兼容层改进后无需重新导入。
若 main.js 执行抛错，导航收集失败但**不影响工具注册**。

⚠️ 注意：装载时执行 main.js 意味着它的**顶层代码会跑**。官方包的 main.js 顶层只做注册，
但第三方包若在顶层写重活（网络请求、大文件读写），会在每次插件重载时执行一次。

## 19. 定时任务与插件间通信（十九期）

### 19.1 定时任务

让插件在 **App 运行期间**按时间点自动执行，不需要用户打开界面。

#### 声明

`plugin.json` 里加 `schedule`，并申请 `schedule` 权限：

```json
{
  "id": "com.demo.reminder",
  "name": "定时提醒",
  "main": "main.js",
  "service": "service/timer.js",
  "permissions": ["schedule", "notify"],
  "schedule": [
    { "id": "poll",    "every": "30m" },
    { "id": "morning", "at": "08:00" }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `id` | 任务标识，回调时原样传回，用来区分是哪个任务 |
| `every` | 固定间隔。支持 `30s` / `10m` / `2h` / `45000`（纯数字按毫秒）。**最小 10 秒**，写更小会被抬到 10 秒 |
| `at` | 每天固定时刻 `HH:mm`（本地时区） |

两者写一个即可；都写时 `every` 优先。

#### 回调

定时任务跑在**服务脚本**的引擎里，所以要有 `service` 入口（不需要 HTTP 能力时 `handleRequest` 可以不导出、`port` 也不用写）：

```js
// service/timer.js
exports.onSchedule = function (taskId, info) {
  // taskId: 声明里的 id
  // info: { taskId, firedAt, pluginId }
  if (taskId === 'morning') {
    ctx.log('早上好');
  }
};
```

只声明合法的 `schedule`、不声明 `service` 时宿主也允许启动后台，但没有脚本就没有 `onSchedule` 回调可执行。要处理任务，请让 `service` 指向实际存在且导出 `onSchedule` 的脚本；不需要 HTTP 时不必申请 `server` 权限。

#### 重要限制

- **调度器跑在 App 进程里**。App 被系统杀掉后不会自动拉起，下次打开 App 需要重新启动该插件后台。
- 用户需要在详情页「插件配置」里手动点启动，定时任务才会开始跑（和服务型插件同一个入口）。
- 回调在 QuickJS 单线程里执行，**不要在里面写死循环或长阻塞**——会卡住该插件的所有其他回调。

### 19.2 插件间通信（ctx.bus）

> 需要 `bus` 权限。

#### 为什么是「拉」不是「推」

每个插件跑在**独立的 QuickJS 实例**里，实例之间没有共享内存。如果做「A 发消息 → 立刻触发 B 的回调」，宿主必须随时跨线程重入别人的引擎，而 QuickJS 是单线程的——轻则阻塞，重则崩溃。

所以总线是**邮箱模型**：发布方投递，订阅方在**自己的**生命周期里主动拉取。

#### API

| 方法 | 说明 |
|---|---|
| `ctx.bus.publish(topic, payload)` | 发一条消息，返回序号。`payload` 传对象会自动 JSON 化 |
| `ctx.bus.subscribe(topic)` | 登记订阅，返回当前最大序号（适合直接当起始游标） |
| `ctx.bus.unsubscribe(topic)` | 取消订阅 |
| `ctx.bus.poll(topic, sinceSeq, limit)` | 拉序号大于 `sinceSeq` 的消息，默认最多 50 条 |
| `ctx.bus.latestSeq(topic)` | 当前最大序号 |

#### 例子

插件 A（发布方）：

```js
await ctx.bus.publish('music.now-playing', { title: '晴天', artist: '周杰伦' });
```

插件 B（订阅方，在界面里定时拉）：

```js
function Screen(ctx) {
  const [now, setNow] = ctx.useState('now', null);
  const [cursor, setCursor] = ctx.useState('cursor', 0);

  ctx.useEffect(async () => {
    const r = await ctx.bus.subscribe('music.now-playing');
    if (r && r.ok) setCursor(r.latestSeq);   // 从现在开始听，不补历史
  }, []);

  // 在渲染里顺便拉一次（也可放在定时任务里）
  const drained = await ctx.bus.poll('music.now-playing', cursor);
  if (drained && drained.messages && drained.messages.length) {
    const last = drained.messages[drained.messages.length - 1];
    setCursor(last.seq);
    setNow(JSON.parse(last.payload));
  }

  return ctx.UI.Column({}, [
    ctx.UI.Text({ text: now ? `${now.title} - ${now.artist}` : '未在播放' })
  ]);
}
```

#### 隔离与容量

- **未订阅的插件拉不到该 topic**，即使知道 topic 名字。这是刻意设计的，避免任何插件监听别人的私有 topic。
- 每个 topic 保留最近 **100 条**，超出丢最旧的。慢订阅者会丢消息——总线不是消息队列，不该无限增长。
- 插件卸载时会自动清掉它的所有订阅。
- 服务型插件同样可用 `ctx.bus.*`，而且它最适合在 `onSchedule` 里把消息排干。

### 19.3 console 日志

以前插件的 `console.log` **被直接丢弃**，什么都看不到。现在会收集起来：

- 打开插件界面 → 右上角 🐛 调试按钮 → 切到「日志」页
- 最多保留最近 300 行，可点「清空」
- 级别前缀：`I`（log/info）、`W`（warn）、`E`（error）、`D`（debug）

```js
console.log('渲染次数', count);       // I  渲染次数 3
console.warn('配置缺失，用默认值');    // W  配置缺失，用默认值
console.error('请求失败', err.message); // E  请求失败 timeout
```

排查「组件没渲染出来」「点了没反应」这类问题时，先在这里打日志，比猜快得多。

### 19.4 服务运行时能用的 ctx

**服务脚本（`service` 字段指向的文件）跑在独立引擎里，可用能力比 UI 面板少**——
它没有界面，所以没有 `ctx.UI`；它是同步执行环境，所以多数方法直接返回结果而不是 Promise。

| 命名空间 | 需要权限 | 说明 |
|---|---|---|
| `ctx.getEnv` / `setEnv` | `env` | 与 UI 面板**同一份**落盘文件，面板改的配置服务能读到 |
| `ctx.exec(cmd, opt)` | `filesystem` | **在容器里执行 shell 命令**（`{ok, exitCode, output}`），详见下 |
| `ctx.http` / `ctx.fetch` | `http` | 同步返回 |
| `ctx.bus.*` | `bus` | 与 UI 侧同一套语义，同步返回 |
| `ctx.chat.runTask` | `chat_task` | 发起 AI 任务，同步返回 |
| `ctx.notify(title, text)` | `notify` | 系统通知，定时任务提醒用户靠它 |
| `ctx.battery()` | `system` | `{ ok, level, charging }`，「仅充电时」「最低电量」条件靠它 |
| `ctx.log(...)` | | 写进 `openx_*.log`（服务没有 UI，这是唯一能看的地方） |

```js
// service/scheduler.js
exports.onSchedule = function (taskId, info) {
  var b = JSON.parse(ctx.battery());
  if (!b.charging) {
    ctx.log('没在充电，跳过');
    return;
  }
  ctx.notify('任务触发', '电量 ' + b.level + '%');
  ctx.chat.runTask('按昨天的方式整理下载目录', { newConversation: true });
};
```

#### ctx.exec：让后台脚本管容器里的进程

有些插件的后台**不在宿主进程里**，而是容器里的一堆外部程序（JVM 网关、Node 服务、二进制）。
这类插件就适合做成「**声明了 `service` 但不申请 `server` 权限**」的脚本——宿主不开端口，
脚本只负责起停：

```js
// service/gateway.js —— 后台是容器里的 node + JVM 进程树
'use strict';

function bashQuote(v) { return "'" + String(v).replace(/'/g, "'\"'\"'") + "'"; }

function bash(script) { return 'bash -c ' + bashQuote(script); }

exports.onStart = function () {
  // 整个启动脚本的输出重定向到文件，避免下面的超时误判（原因见下方硬约束）。
  const r = ctx.exec(bash([
    'node panel/launch.js',
    'node -e "const s=require(\'./panel/lib/gateway\'); if(!s.start().ok) process.exit(1)"',
    'echo BOOTSTRAP_DONE'
  ].join('\n')) + ' > \"$HOME_DIR/runtime/bootstrap.log\" 2>&1', { timeoutMs: 30000 });
  if (!r.ok) {
    const log = ctx.exec('cat "' + HOME_DIR + '/runtime/bootstrap.log"', { timeoutMs: 3000 });
    // 超时且写出了完成标记 → 继续看服务是否真的起来了，不能直接判失败。
    if (r.exitCode != null || !log.ok || !log.output.includes('BOOTSTRAP_DONE')) {
      throw new Error('启动失败：' + (log.output || r.error || r.output));
    }
  }
  // 服务 ctx.http 返回 JSON 字符串，不是对象。
  const health = JSON.parse(ctx.http({ url: 'http://127.0.0.1:18791/healthz', method: 'GET' }));
  if (!health.ok || health.status !== 200) throw new Error('端口未就绪');
};

exports.onStop = function () {
  ctx.exec(bash('kill "$(cat /root/aigw/runtime/gateway.pid)" 2>/dev/null || true'));
};
```

几条硬约束：

- **同步阻塞**：`ctx.exec` 一直等到**命令的 stdout 到达 EOF** 才返回，或超时（默认 20s，上限 45s，受引擎看门狗约束）。
  所以启动常驻进程的命令必须自己结束，否则这个调用会挂到超时，表现为「点了启动一直转圈」。
- **detached 子进程仍可能继承 exec 的输出管道**：写上 `setsid xxx </dev/null >/dev/null 2>&1 &` 也不保证
  父 shell 退出后管道就关闭——proot 下实测过，命令早已写完 `BOOTSTRAP_DONE`，宿主仍等满 30 秒判超时，
  `exitCode` 为 `null`。**可靠做法**：把启动脚本输出整个重定向到文件，超时后再读文件里的完成标记；
  确认标记后再对服务端口做一次真实健康检查，而不是只信 `r.ok`。
- **`exitCode` 判断要用 `!= null`，别写 `=== null`**：超时结果经 JSON 往返后，`exitCode` 字段可能被
  **整个省略**（插件侧读出来是 `undefined`），此时 `exitCode === null` 不成立，会把「已启动但等管道超时」
  误判成失败。只有**非零退出码**才应判失败。
- **服务侧 `ctx.http()` 返回 JSON 字符串**，不是对象，用之前先 `JSON.parse`；
  可用它做启动后的健康检查（UI 侧的 `ctx.http` 返回 Promise，两者不是一回事）。
- **`onStart` 抛异常要直接抛**，不要只 `ctx.log`：宿主会把它作为启动失败传给配置页显示。
  只写日志会让按钮显示「已启动」，实际服务没起来。
- 需要 `filesystem` 权限。
- **宿主不会因为你停脚本就去杀你起的容器进程**（那是独立进程），该在 `onStop` 里自己收尾。
- 脚本侧**没有 `ctx.sleep`**。`setTimeout` 虽然引擎有，但 `onStart` 阻塞在 `ctx.exec` 期间
  定时器不会推进——要等待就让命令自己 `sleep`。

> 服务运行时的 `NativeInterface` 与 UI 侧是**两份独立实现**（见下面第二个坑），
> 所以 `ctx.exec` 只在服务脚本里可用；UI 面板要执行命令请用兼容层的 `Tools.System.terminal`。

#### 容易踩的两个坑

**① `onSchedule` 收到的 `info` 是对象，不是 JSON 字符串。**
宿主传给 JS 的实参是 JSON 数组（`callFunction` 的约定：参数对应实参列表），
兼容层已帮你拆好第一个元素。所以直接用 `info.taskId` 即可。

**② 服务运行时的 `NativeInterface` 与 UI 侧是两份独立实现。**
给 UI 侧加一个 `ctx.xxx` 不代表服务侧也有——两边都要在各自的 bridge 里实现，
漏了会报 `NativeInterface method not found: openxXxx/N`。
`ctx.chat.runTask`、`ctx.notify`、`ctx.battery` 都是两边都有的。

## 20. 会话状态（ctx.host.session）

让插件知道「AI 现在在干什么」。典型用途：桌宠跟着换表情、状态栏挂个指示灯。

### 20.1 声明权限

```json
"permissions": ["session"]
```

不需要用户额外授权，声明即生效。

### 20.2 读快照

```js
var s = ctx.host.session();
// {
//   ok: true,
//   busy: false,          // 这一轮对话是否在跑
//   thinking: false,      // 在思考（已发起、还没调工具）
//   tool: null,           // 正在跑的工具名，如 "terminal"；没在跑工具为 null
//   pending: null,        // 等用户操作："approval" | "terminal" | "question"
//   contextTokens: 0,     // 当前上下文占用 token 估算
//   reconnecting: false   // 连接断开、正在重连
// }
```

**只给状态，不给内容**：没有用户消息、没有模型回复、没有工具参数，所以不算危险权限。

`ok: false` 表示宿主还没准备好（App 刚起来、还没进过对话页），此时其余字段都是默认值。

### 20.3 采样频率

同步调用，但**不要每一帧都读**。界面里的心跳定时器一般 250ms 一跳，
每 10 拍读一次（约 500ms）足够——状态变化没那么快：

```js
refs.tick.current++;
if (refs.tick.current % 10 === 0) {
    var s = ctx.host.session();
    if (s.ok && s.busy !== refs.busy.current) {
        refs.busy.current = s.busy;
        // 换图 / 说话
    }
}
```

### 20.4 优先级怎么取

几个字段会同时为真，按你想要的语义挑：

| 想要的语义 | 判据 |
|---|---|
| 等用户动手（最该提醒） | `pending != null` |
| 连接出问题 | `reconnecting` |
| 正在跑工具 | `busy && tool` |
| 正在思考 | `busy` |
| 上下文快满 | `contextTokens >= 60000` |

> 判断「在思考」不能只看 `busy`——跑工具时 `busy` 同样为真。
> 也**没有** `streaming` 标志：「已经吐字但还没结束」这个态宿主不暴露，用 `busy && !tool` 近似。
